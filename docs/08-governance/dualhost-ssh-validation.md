## 新实验假设（用户所称新“特权”）

接受 A、B 为两台独立物理执行主机，具有分别管理的进程、运行目录与持久化状态。
这是本轮有限实验的用户接受假设，不是已证明的物理/统计独立性。
同一局域网、同一操作者、相同软件、可能共享的供电仍有相关故障；不推导身份独立、Sybil 抵抗、统计支持能力上界或生产 TRUSTED。
不得用共享目录、同一状态副本或同一主机上两个角色冒充跨机部署。权威服务与接纳端若同机，必须明确记载该共同故障范围。
发现实际只有一台主机、状态目录共享、控制关系或拓扑变化时，暂停对应双机结论，记录失效并重新验收；其余本地回归可继续。
本约定持续适用于后续工作，直到用户撤销或拓扑变更；每次实验均记录适用版本和当前拓扑。

## 连接记忆（可随 DHCP 变化）

- A：本机，hostname `inpax-aki`，主仓库 `<A_REPO>`。
- B：Ubuntu 26.04.1 LTS x86_64，hostname `aki2`，用户 `<B_USER>`，当前地址 `<B_IP>:22`。
- 方向：A → B；无需为此在 A 启用 SSH 服务端。
- 命令：`ssh -F /dev/null -o BatchMode=yes -o StrictHostKeyChecking=yes <B_USER>@<B_IP>`。
- 2026-10-23 已实际验证 BatchMode 免密命令成功；主机密钥使用本机已有 known_hosts 严格检查。
- `-F /dev/null` 用于绕过本机此前 `/etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf` 的所有权/权限错误；该系统问题尚未修复。
- 不复制、展示或提交私钥/密码，不关闭主机密钥检查。
- 实际 IP、用户名和本地路径不入库，由操作者本地保存；文中以 `<A_IP>`、`<B_IP>`、`<B_USER>`、`<A_REPO>`、`<EVIDENCE_ROOT>` 占位。

## 下一轮最小双机验收

先迁移已有 `experiments/aclt-authority-admission/` v2 的运行与证据采集方式，不改变协议语义或旧 VM 历史。
该 Python/C++/OpenSSL 实验首轮不要求远端 Rust；后续远端完整回归或编码对拍才补齐 Rust/Cargo。

1. 固定两端同一源码快照及内容摘要，B 使用新建独立实验目录；保留远端已有文件。记录工具、空间、文件系统和运行标识。
2. 首轮 A 放权威服务和接纳转发端，B 放 worker 和本地持久状态；真实任务请求跨 LAN TCP。SSH 负责控制和证据回收，不能以单独 SSH 远程运行命令替代任务协议验证。
3. 跑通正常授权→执行→结果提交→稳定回执，再覆盖完整结果重传、冲突结果、错误结果、响应丢失、服务进程重启与受控连接中断。只操作实验进程和端口，不断开管理 SSH。
4. 需要双方运行 worker 的角色互换场景另行登记；两台主机不等于三个独立故障域，不声称复现五台 VM 的全部分离条件。
5. 保存命令、退出码、源码/配置摘要、原始日志、资格占用、启动意图、完成调用、接纳贡献与回执，进行离线核对。现有离线检查器依赖 VM 目录时需先适配，不能直接声称兼容双机证据。
6. 真实断电、权威账本自身回滚、恶意 worker、主网和统计独立性仍不在本轮结论内。进程终止不冒充整机断电。

通过标准：可重放证据支持每个已声明场景；每个 claim/unit 无额外资格或计算重试；重复结果保持原回执；错误/冲突不覆盖原贡献；断连不授权离线计算。失败现场保留，不用修改验收规则将失败转为通过。

## 与规范的关系

沿用 ADR-0005 与 CONTRIBUTING 的证据分层。此处仅接受有限实验环境假设；不改变规范 SemanticStatus、VersionDisposition、统计参数、判决、Gate 或生产准入。
历史 ENV-1 中的 VM 复现说明仍供历史审计，后续选择以本约定为准。
