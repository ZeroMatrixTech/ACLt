# ACLt 审查与验收

> 2026-11-19：本轮由维护者审计，按[当前开发政策](../development-policy.md)执行。

## 1. 审查对象

每次审查记录具体改动、源码基线和实际运行。依据是实现行为、输入输出、模型条件、测试结果与维护者决定。工程约定可以随维护者的当前工作调整；审查直接回答改动解决了什么、还有什么需要处理。

## 2. 提供的材料

- 行为变化与涉及的对象、接口和状态；
- 有代表性的合法输入、相关反例与实际运行结果；
- 使用的数学前提、工程条件及证据入口；
- 保留的旧数据、失败记录及迁移方式；
- 需维护者判断的事项。

同一个事实在一处记录，其余位置引用。检查规模按变更影响选择。模板、当前说明、研究稿和历史报告分别按用途审查，正文 H1 等格式规则不套用于 GitHub 表单模板。

## 3. SHA 条目的本轮处置

SHA 清单、源码和工件 pin、对象与协议摘要的复算和相等判定按本轮决定停用；运行入口的同步情况按本次差异和检查记录确认。旧 owner SV 和覆盖计数作为历史信息；摘要字段继续记录。检查报告应写明哪些内容、结构或状态关系实际执行了，SHA 条目不记作本轮通过。

## 4. 数学与工程证据

数学陈述写出对象、前提和适用范围；有限测试报告其实际输入；设计选择写成选择。#213、#215 等待维护者研究的事项继续跟踪。代理交付事实与反例，维护者或指定的人类协作者给出模型。

## 5. 记录与处理

维护者审计本轮整肃并决定合并。代理保留具体差异、命令和退出码，对修复后的反例做相关复查。历史审计正文、原始失败和发布快照保留原字节，新结论单独记录。

当前审核不再要求为每个修改完整执行原 A0—A10 模板、强制生成多份同步清单或追加独立代理审计。既有审计报告保留其原程序、日期与结论。
