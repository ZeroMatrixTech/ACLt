## 3. 四类问题的最终核对

### 3.1 固定协调器、角色和地址

规范层没有以实验 A 节点取代可检查的授权条件。`protocol-spec.md:150` 允许任意 Principal 规划；`identities-and-roles.md:34` 起把 Compile、Plan、Schedule、Verify、Aggregate 等列为可复算职能；`system-architecture.md:183` 明确组件不是协议必需实体。正式 Lease 的持久 epoch、Provider 接受、当前 capability、旧 epoch 隔离仍然存在（`protocol-spec.md:175–183`）。

实验层的权限与工作服务鉴别并非同一机制：可信宿主依进程生命周期串行指派并隔离日志写入；工作服务依固定源地址接受请求。M9 可支持“可信宿主下的无在途交接及注入冲突停止”，不能支持任意远端实例自证有权接手。工作进程重启后去重丢失，也不能据现有记录声称跨重启的最多一次执行。A-02 至 A-04 是 C 线的主要证据缺口。

[#121 的确认](https://github.com/ZeroMatrixTech/ACLt/issues/121#issuecomment-6881847017)只接受可信单宿主范围；前一条细则明确排除失联与宕机无法区分的分区/物理场景。不能把该 CLOSED 状态外推为 M4 一般恢复已解决。

### 3.2 固定统计工件与一般任务

固定统计工件的切片、局部坐标、树归并和正常输出等价都有明确条件。通用契约另外要求任务族给出可检查的分解与组合关系；整数向量任务族及固定容量排序已经有不同的任务规则。排序对照证明的是固定镜像中持久交付容量，求解可用内存，不能解释为“任意任务均突破单节点内存/计算上限”。

[#114 的维护者决定](https://github.com/ZeroMatrixTech/ACLt/issues/114#issuecomment-6880955352)接受固定工具、格式和容量配置下的实测实例，不要求推导所有输入。[#120 的确认](https://github.com/ZeroMatrixTech/ACLt/issues/120#issuecomment-6881846750)则允许冻结 question_id 完全相同的证据复用，资源上限不放宽；不是任意槽位或任意资源变化的迁移定理。

TG-5（[#122](https://github.com/ZeroMatrixTech/ACLt/issues/122)，本次读回 OPEN）仍覆盖一般工件资源界、多限制 trap 与完整 Outcome 组合。当前文档没有把这些待证性质改为已成立。

### 3.3 计量与成本

现有预算不变量是“已计入求解用量 + 在途预留 ≤ 实例求解预算”，并非全资源预算。失败前已执行但无答复的尝试按冻结额度计入，实际值未知；这是一项保守求解账规则，不是故障率、期望重试成本或真实耗费估计。

本次核对没有发现把固定 gas、排序记录数、常量净荷字节直接相加的通用成本结论。但也没有形成求解、复核、通信、归并及失败尝试全部独立实测的完整账；原始帧和 verdict 不能自动补齐这项义务。TG-6（[#123](https://github.com/ZeroMatrixTech/ACLt/issues/123)）与 TG-7（[#124](https://github.com/ZeroMatrixTech/ACLt/issues/124)）均仍 OPEN；任何后续成本收益、概率预算或单位换算结论须另有依据。

### 3.4 证据层级

- 本地单元/模型/对拍：本次新执行的 163 项回归，只证明本次固定环境下相应测试通过。
- 同宿主多来宾：M2/M9 联合验收，覆盖固定任务、共享尝试账、接纳与可信宿主静止点交接；不能证明物理故障域分离。
- 两物理主机：M3、容量排序及 R2/R4，提供指定拓扑中的 LAN 与固定用例证据；两台物理机本身不证明控制者、故障或统计独立。
- R4：固定种子两遍共 64 run、0 violation 的历史结论受 R1 修订 1 限制，不是故障概率、覆盖率、完成率或一般恢复证据。

[R1 修订 1 的维护者决定](https://github.com/ZeroMatrixTech/ACLt/issues/150#issuecomment-6899101582)明确接受固定派活、可信协调者，允许将不同 VM 交互作为该故障判据，并保留实际物理放置记录。本报告原样承认其范围，不评价决定对错。`invariants.md:600` 同样明确工程假设不是无条件不变量。
