# 多分支协作

> PARALLEL-1；2026-11-19。当前执行按[开发政策](../development-policy.md)。

## 1. 分工

维护者确定方向、处理数学建模、审计并合并本轮整肃。代理负责授权范围内的实现、内容核对、测试和残留事项记录。组织内的人类协作者可按维护者安排参与实现和研究。

本轮维护者已经授权仓库整肃；已授权事项按当前分工推进。新增问题先说明其实际影响；需要数学定义或政策选择时整理事实交维护者，独立工作继续进行。

## 2. 工作目录

主检出用于协调。并行条目使用独立 worktree；同一文件只交给一个写入者。采用共享 worktree 时，先明确彼此独占的文件范围。过程草稿、日志和报告放在代理专属目录。

## 3. 并行与同步

以文件范围和运行资源决定并行。修改同一核心模块的工作串行；改动相互独立时并行推进。共享入口的修改在交付前合并核对，保留双方已经发生的记录。

分支更新使用普通 merge；代码差异和实际检查决定同步是否完成。本轮不刷新或验证 SHA 清单，旧摘要和 pin 作为记录保留。

## 4. 审计与交付

本轮由维护者审计。代理提供行为变化、实际验证、兼容影响和待处理问题，不为每个小修改增加独立审计会话或多份同义状态表。其他阶段的审计方式由维护者按工作安排。

代理提交不加 DCO 签名，不直接合并或推送 main；维护者负责签署和合并。当前组织外 PR 暂停接收。

## 5. 研究依赖

已有理论问题继续引用原 Issue。使用某个待证性质的陈述注明其依赖范围；代理整理事实、反例与实验，不替维护者建模。未依赖该性质的实现继续推进。

目前 #213 对应全域 Schema View 往返，#215 对应活性推广；B1 的明确支持域实现继续进行。新公式、参数估计和数学主张由维护者或指定的人类协作者处理。

## 6. 实验资源

多虚拟机和双物理机运行取得宿主级共享锁。证据运行记录并发负载；同一共享实验资源由一个运行使用。SSH 沿用严格主机密钥检查，凭据由操作者保管。

## 7. 历史流程

本文件原有计划卡逐次批准、代理独立审计、强制全仓同步、清单刷新和额外审查层级作为此前流程保存在 Git 历史。本轮按当前维护者授权和本文执行，保留实现差异、失败记录、许可与签署责任。
