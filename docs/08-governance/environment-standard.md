## 1. 实际环境与支持信息

环境记录用于解释运行结果。记录操作系统与架构、Python/Unicode、Rust/Cargo、C++、OpenSSL 和本次使用的工具路径。协作中已使用 Ubuntu x86_64、Python 3.14/Unicode 16.0.0、Rust/Cargo 1.93.1、G++ 15 与 OpenSSL 3.5；这是已有运行环境。维护者可根据实际支持能力调整工具版本，版本标签本身不作为测试通过或拒绝使用环境的理由。

Unicode 数据版本影响规范化结果，固定编译工件可能依赖其构建环境。测试报告分别记录这些输入及工具版本，用行为对照判断变更影响。

## 2. 当前入口

```bash
make help
make check
make test
```

本地检查按实际需要使用 Python 标准库、Rust/Cargo、C++17、OpenSSL 与 Linux 进程/文件系统能力。源码交付文件由交付范围选择，SHA 清单、源码 pin 和协议摘要一致性门禁按本轮决定停用，实施情况见本次运行记录。

运行前核对工作目录与本次改动，运行后记录命令、退出码和结果位置。失败日志保留，并据此区分输入、实现和环境问题。

## 3. 文件与工作目录

一个目录同时由一个写入流程操作。条目 worktree 与过程文件按本机代理工作区约定存放，源码检出保持可审查。任务数据、编译缓存与证据记录各用清晰目录。

现行实现使用文件锁、原子重命名、同步和 Linux 进程机制。测试报告记录实际文件系统和宿主条件；在新环境运行时直接验证相关机制，而不是从操作系统名称推定结果。

## 4. 多来宾和双物理机

本地多虚拟机路径继续用于来宾间通信、角色分工和来宾故障实验。报告记录共同宿主、来宾、加速方式及网络。物理双机运行按 [DUALHOST-SSH-1](dualhost-ssh-validation.md) 记录实际拓扑并取得共享实验锁。

两台独立物理机是有限实验采用的条件。每份报告分别说明物理主机分离、虚拟来宾分离及实际观察的事件。物理机授权沿用维护者对当前阶段的决定。

## 5. 交接与当前政策

交接提供源码基线、工作区状态、运行命令、环境、输入、通过和失败结果及后续工作。摘要可作为记录字段，但本轮不把其相等性作为验收条件。

本轮由维护者审计，决定停用 SHA 验证，组织外 PR 暂停接收；运行入口的实施情况按本次差异和检查记录确认。旧环境规范里的精确版本门禁、强制清单刷新及额外审批流程由[当前开发政策](../development-policy.md)取代。具体实验的原报告保留当时条件和结果。
