# 维护工作与协作成本

> 2026-11-19。当前分工见[开发政策](../development-policy.md)。

## 1. 已有维护工作

项目维护包括源码和文档修订、问题跟踪、发布、许可来源记录、安全问题处理与实验协调。本轮由维护者审计并决定合并，代理提供实施和实际检查结果。

## 2. 比较一项流程

新增或保留流程时，说明它处理的具体问题，以及已经观察到的收益和成本：

| 方面 | 可记录的事实 |
|---|---|
| 工作量 | 修改文件数、同步位置、运行时间与审查时间 |
| 问题发现 | 检出的行为差异、复现输入、误报及重复检查 |
| 协作 | 排队、冲突、交接和所需参与者 |
| 运行 | 计算、存储、通信与实验资源占用 |
| 权限 | 哪些组件或人员可以改变什么，以及实际责任 |

不同成本量可以分别记录。共同计量单位与换算若尚未确定，继续沿用 TG-7 #124 的研究。以这些事实比较简化方案，由维护者决定保留和调整的步骤。

## 3. 当前简化

本轮停止将 SHA 一致性清单和协议摘要复算作为判定，摘要字段保留记录；各入口的同步进度按本次实现记录。日常更新只维护实际受影响的位置，解释性材料引用已有定义。本轮审计由维护者承担，组织外 PR 暂停接收。

## 4. 研究与实现

实际协议状态、资金权利和验证结果由对应输入与实现处理；开发审计与运行时职能分别说明。后续组织、发布或应急机制按具体需要比较。早期净价值公式、组织准入门槛和完整流程清单保留在 Git 历史，本轮采用上述事实比较方式。
