# ACLt Protocol 行政成本与治理扩张分析

> 文档状态：Living cost–risk analysis  
> 语义基线：v0.5  
> 当前决定：保留最小 Maintenance Boundary；允许其为 ACLt 官方主网承担有限保障与日志运营；组织形式 `OPEN/POLICY`
> 最后更新：2026-08-21

## 1. 问题

维护、漏洞响应、发布、法律、仲裁和治理都可能降低风险，也可能引入费用、延迟、寻租、审查和新的信任根。本文件回答：何时一项行政职能值得存在，何时应由公开协议算法取代，何时应被删除。

“有帮助”不足以证明应新增实体；必须比较净风险变化和完整生命周期成本。

## 2. 行政成本范围

| 类别 | 例子 | 可量化指标 |
|---|---|---|
| 人力 | 规范评审、发布、漏洞处理、合规 | 工时、人员数、响应时间 |
| 决策延迟 | 审批、委员会、申诉 | 排队时间、错失任务价值 |
| 基础设施 | 签名、审计、备份、披露渠道 | 固定/变动成本、可用性 |
| 执行规范维护 | Logical Object、RIR、Rust Profile、RPR/Host OS capability、Compile/Dispatch、golden vectors 与未来 frontend conformance | 评审工时、实现数、回归规模、兼容失败率 |
| 版本与审计 | SemanticStatus registry、V1 Profile、ADR、审计和历史隔离 | CORE 阻断数、状态漂移、审计工时和重复权威数 |
| 主网保障 | 部署审计、MainnetAssuranceProfile、紧急暂停、范围与证据维护 | 覆盖率、误暂停率、响应时间、保障失效造成的损失 |
| 日志与来源 | 追加式终局日志、透明度证明、访问审计、备份与故障注入 | 最终性延迟、缺失率、恢复时间、审计异常率 |
| 接口一致性 | CauseSet/reducer、ExecutionCapability、Dispatch/RPR 对拍 | 向量数、实现分歧率、错误拒绝率、竞态失败率 |
| 权限风险 | 密钥、管理接口、人工覆盖 | 影响面、单点故障、滥权概率 |
| 法律与地域 | 法人、税务、数据、劳动、支付 | 专业费用、限制和责任 |
| 协调 | 会议、分歧、版本迁移 | 决策周期、分叉概率 |
| 机会成本 | 延迟研究/实现、参与门槛 | 周期、流失、创新损失 |
| 隐私 | 人工审查控制关系或证据 | 数据量、访问者、保留时间 |

## 3. 必需维护职能

当前最小边界包括：

- 维护规范、Schema、状态机和测试；
- 评审 ADR、兼容性和版本；
- 管理发布签名、密钥轮换和撤销；
- 接收、修复和披露漏洞；
- 发布参考实现与 conformance suite；
- 维护 Logical Object、RIR、Rust Profile、RPR、Compile/Dispatch 一致性材料及未来 frontend 准入测试；
- 维护 SemanticStatus 与 VersionDisposition 的分离登记、审计程序和 Gate 证据；
- 保存公开变更、证据和历史版本。
- 为 ACLt 官方主网维护版本化、只能收紧能力的保障 Profile、追加式日志与应急暂停流程。

这些是项目维护责任，不是运行时协议身份。

## 4. 明确排除的行政权力

维护者、基金会或委员会不得：

- 修改冻结 Receipt、Snapshot 或 FundingPolicy；
- 针对个案改变验证权重或停止规则；
- 覆盖 TRUSTED/UNRESOLVED 或其他终态；
- 制造结算、退款或未授权资金；
- 把维护意见当作优先证据；
- 把 FoundationReport、委员会报告或维护报告写入 Bayesian prior、VerificationEvidence 权重或停止条件；
- 因组织地位获得 Provider/Requester 之外的协议权利。
- 把官方主网保障结论外推到未审计网络，或用保障 Profile 放宽个案规则。

如果某种事故只有依赖这些权力才能处理，必须优先改进协议的安全终态、版本、撤销或追加更正机制。

## 5. 可选组织方案

| 方案 | 优点 | 成本与风险 | 当前判断 |
|---|---|---|---|
| A. 维护者集合，无独立法人 | 最小、灵活、成本低 | 密钥和人员集中，法律承载弱 | 当前默认 |
| B. 非营利基金会 | 可承接资金、合同、主网保障、日志与长期治理 | 法律、人员、寻租、误暂停和品牌控制 | `OPEN`；可作为官方主网运营主体，非协议 Principal |
| C. 技术委员会/多签发布 | 分散发布与评审 | 决策慢、联盟捕获、责任模糊 | 可作为发布实现候选 |
| D. 链上治理/代币投票 | 可公开执行部分规则 | 财富权、投票操纵、升级复杂 | 不进入当前核心 |
| E. 商业运营主体 | 工程和服务责任清晰 | 平台捕获、利益冲突和中心化 | 仅实现层可选 |
| F. 完全自动化、无人维护 | 最小人工裁量 | 无法修复漏洞、升级和兼容 | 不现实，拒绝绝对化 |

组织形式不改变 INV-15；任何方案都不得获得个案裁决权。

## 6. 净价值模型

对候选行政职能 `g`，只在以下条件成立时考虑引入：

\[
NV(g)=\Delta ExpectedLoss(g)+\Delta RecoveryValue(g)
-C_{direct}(g)-C_{delay}(g)-C_{trust}(g)-C_{privacy}(g)>0
\]

其中：

- `ΔExpectedLoss`：预期安全/操作损失降低；
- `ΔRecoveryValue`：恢复、披露、兼容和法律承载收益；
- `Cdirect`：直接人力与基础设施；
- `Cdelay`：审批和协调延迟；
- `Ctrust`：新增权限、单点、捕获和滥权风险；
- `Cprivacy`：额外收集和人工访问数据的成本。

若数值无法可靠估计，至少必须给出范围、敏感性、最坏情形和反证条件。

## 7. 新行政实体准入门槛

必须同时满足：

1. 有具体、重复出现且高影响的失败模式；
2. 协议算法、permissionless function 或实现自动化无法充分处理；
3. 权限最小化且能机器测试；
4. 失陷影响有硬上限和撤销路径；
5. 决策、资金、利益冲突和 recusal 公开；
6. 定期复审并可以缩减或解散；
7. 净价值在合理参数范围内为正；
8. 通过 ADR、威胁模型和不变量审查。

## 8. 自动化优先矩阵

| 职能 | 首选方式 | 人工仅在何时介入 |
|---|---|---|
| Receipt 合法性 | Schema/确定规则 | 设计新版本规则，不裁决个案 |
| WorkPlan 合法性 | 可复算算法 | 修复算法或定义新任务类型 |
| 准入与暴露 | Evidence/Estimate/Policy | 校准未来模型，不手工提额 |
| 结果验证 | Registry + Sample/Verify/Aggregate | 修复未来验证器，不覆盖 Decision |
| 结算 | 终态和政策确定计算 | 修复通道/实现，不制造权利 |
| 证据更正 | 追加式证据流程 | 审核来源时仍不得改历史 |
| 发布与漏洞 | 人工评审 + 可验证发布 | 必需，但权限只作用未来版本 |
| 主网保障 | 版本化 Profile + 证据门槛 + 只能收紧的自动执行 | 人工决定未来保障范围，不得重判个案 |
| 日志忠实性 | 追加式日志、透明度证明、访问审计、故障注入 | 调查异常和修复实现，不把“格式有效”当“来源真实” |

## 9. 行政成本仿真

至少比较：

- 无独立组织 vs 维护者集合；
- 单签 vs 多签/委员会发布；
- 自动化披露/撤销 vs 人工审批；
- 有/无申诉或证据更正流程；
- 不同事件率、损失规模和响应时限。

输出包括：安全损失、响应时间、发布延迟、误处置、参与门槛、固定成本、隐私访问和捕获风险。

## 10. 扩张与收缩触发器

### 可以考虑扩张

- 同类严重事故重复发生且自动机制不能处理；
- 发布密钥或漏洞响应成为可测单点；
- 外部资金、合同或责任必须由法人承接；
- 多实现兼容性争议无法由 conformance suite 解决。
- 官方主网出现重复部署事故，而版本化保障与日志运营能在有限范围显著降低损失。

### 必须考虑收缩

- 人工决定开始影响运行中个案；
- 行政延迟或费用超过降低的损失；
- 组织捕获、利益冲突或密钥集中上升；
- 自动化已经能完成同一职能；
- 参与者为规避治理而分叉或退出。

## 11. 当前严格结论

v0.5 需要 Maintenance Boundary，但基金会、委员会或链上治理仍不是协议 Principal。工程上允许基金会或等价组织为 ACLt 官方主网承担有限保障、追加式日志和安全响应；权限必须绑定网络与范围、只能收紧能力，并禁止个案裁决。是否值得长期组织化，由事故率、响应收益、误暂停、行政成本和捕获风险共同决定。

## 12. 未决问题

- 发布密钥、多人审批和紧急撤销；
- 漏洞渠道、保密期和披露 SLA；
- 贡献许可、项目许可证和法人责任；
- 证据更正、recusal 和利益冲突；
- 不同治理方案的事故率与成本参数；
- RIR/toolchain/runtime 多实现审查、供应链响应和长期兼容的实际维护成本；
- 何时值得建立独立组织；
- 如何确保组织可以缩减或解散。
- MainnetAssuranceProfile 的保障预算、发布门槛、误暂停容忍度与责任边界。

## 13. 更新规则

任何新增管理接口、人工例外、组织、委员会、基金、治理投票或法律主体，都必须更新本文件、ADR、Threat TH-30/31、INV-15、权限矩阵和 open questions。
