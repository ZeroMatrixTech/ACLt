# ACLt 自动进度流程模板

> 最后更新：2026-10-14

目标：把“跑测试、收证据、更新进度、列待办”变成一次操作。人工只处理规则选择与负责人，不再逐项抄写测试数量。

## 安装与使用

本模板已安装在主仓库的标准目录，无需另外覆盖更新包。仓库中应已有 `experiments/aclt-minimal-verifier-state3/`、扩展验证器与相应测试。本工具使用 Linux 和 Python 标准库，不添加第三方依赖。

在仓库根目录运行：

```sh
python3 scripts/aclt-flow.py run
```

统一维护操作见[开发与维护指南](../development.md)。

它会依次检查流程工具和仓库集成、模型、验证配置、单机实验及多节点原型的本地检查；收集输出与测试 JSON；记录代码文件指纹、Git 提交（若有）、工具版本、相关构建环境摘要和执行命令；最后生成根目录 **ACLT-PROGRESS.md**。

以后还是同一条命令。已通过且登记输入、工具环境与证据未变化的任务会跳过；修改过的任务会重新运行。失败任务可以修复后直接重跑。无需人工填写通过数量。

只刷新看板、不运行测试：

```sh
python3 scripts/aclt-flow.py status
```

运行中直接打开 ACLT-PROGRESS.md 查看各组状态与日志链接。为避免竞争，另一流程正在更新时，命令入口会提示稍后查看。

显式全量重跑：

```sh
python3 scripts/aclt-flow.py run --force
```

## 自动维护的内容

| 内容 | 保存位置 |
|---|---|
| 面向人的进度、摘要、待办 | ACLT-PROGRESS.md |
| 本次有效状态、来源与指纹 | .aclt-flow/state.json |
| 每次独立运行的命令、环境、日志、证据副本 | .aclt-flow/runs/时间-编号-工作项/ |
| 从规范正文与覆盖登记重新生成的逐条规则状态 | .aclt-flow/rules-status.json |
| 工作项定义、输入范围、人工决定 | .aclt-flow/template.json |

运行记录以唯一目录保存，不覆盖过去记录。文件通过临时文件与替换更新；本工具没有声称提供数据库事务或断电安全。运行记录默认由本目录的 .gitignore 排除，避免把临时状态或本机缓存上传成别人的有效结果。审阅时可以分享所需运行目录与看板；示例看板随本包提供。

## 状态处理

- NOT_RUN：首次运行。
- RUNNING：正在执行。并发入口被文件锁阻止；锁也传给测试主进程，避免登记进程中断后立即重复启动同一测试。
- PASS：退出码为 0、预期测试组摘要齐全、登记输入运行前后未变。
- FAIL / TIMEOUT / INTERRUPTED：失败、超过时限或未完成登记，不能自动升为通过。
- INCOMPLETE_OUTPUT：命令退出成功，但缺少约定的测试摘要。
- SOURCE_CHANGED：运行过程中代码、绑定决定、任务定义或已检测环境发生变化，需要重跑。
- STALE：先前通过，但当前指纹不同。
- EVIDENCE_INVALID：已保存的日志或证据副本缺失、校验不符。
- BLOCKED_DECISION / BLOCKED_DEPENDENCY：需要先作决定或完成前置工作。

模型、验证器和实验分别登记输入范围，避免一个文件改变就重跑所有组。工具版本、已登记环境以及执行器自身变化会使相关结果失效。它不是完全隔离的构建环境；怀疑未登记的宿主变化时使用 --force。历史报告不会自动导入为当前 PASS。

## 少量人工维护

打开 `.aclt-flow/template.json` 的 `decisions`：给三个已有问题填写负责人；确定规则后填写 `decision`，再将 `status` 改为 `DECIDED`。没有书面决定不能标记已决定。

模板已有三个问题：任务何时永久结束、正式恢复依据、资源账本范围。选择必须依据正式规范或审阅决定；工具不会替人选择规则，也不会把测试通过当作理论成立。

将来增加正式流程测试时，为新工作项添加：

- `command`：参数数组，无隐式 shell 拼接。
- `inputs`：所有影响此任务的代码、输入和规则文件；遗漏依赖会导致错误复用，新增组件时同步维护。
- `required_output`：必须出现的摘要；以 `re:` 开头可使用正则。现有模板自动接受新增测试数量，不要求每次人工改数字。
- `timeout_seconds`：任务最长运行时间，最多 86400 秒。
- `evidence`：需要归档的输出文件模式。
- `needs`：前置工作项 ID，须在模板中排在当前项之前。
- `requires_decisions`：需要已经登记决定的问题 ID。

未决定的问题会阻止依赖它的新工作项；无关测试仍可执行。绑定的决定改变后，其测试结果失效；单纯整理不相关决定不会强制重跑已有测试。

## 验证与边界

执行器自身的测试入口：

```sh
python3 -B -m unittest discover -s tests/workflow -v
```

2026-10-07 版本用 22 项流程与仓库集成测试验证结果复用、代码与环境变化、失败、超时、摘要缺失、证据丢失/篡改、并发排斥、决定与任务依赖等行为，当日在隔离工作副本重跑这 22 项测试通过；2026-10-03 的全量集成证据见 [集成修复报告](../testing/INTEGRATION-FIX.md)。

当前新增交付回归检查和多节点本地工作项；该工作项不运行 VM，也不将外部 VM 报告导入为当前结果。历史示例看板保留原分组和证据。

`PASS` 只表示这次约定的测试执行通过。规则是否完整实现仍从覆盖登记读取；未实现规则不会被自动改为通过，协议 Gate 不会自动关闭。记录不是签名或防篡改审计系统；本机用户仍能改写记录。

本模板不创建后台常驻进程、不安排定时任务、不自动提交/推送/合并。现阶段通过一个入口减少重复登记；如以后接入 CI，可直接复用同一入口。内存检测要求运行环境支持 LeakSanitizer；受 ptrace 限制时保留失败证据并在受支持环境重跑，不把禁用检测记为通过。
