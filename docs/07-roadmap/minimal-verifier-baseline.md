# ACLt 最简验证机

> 文档状态：工程立项与乌托邦基线实验规格草案<br>
> 决定来源：维护者于 2026-11-11 确认以「问—答—验」为内核，乌托邦基线覆盖可信多机分布式计算<br>
> 语义边界：v0.5；实验接口为候选设计，V1 处置见 [V1 Profile](../03-protocol/v1-profile.md)

## 目标与范围

乌托邦基线是在参与者诚实、网络和机器正常、单一协调记录方且无资金结算的环境中，完成一次真正的分布式作业。作业经过请求、拆分、跨机派发、执行、验证和归并。首个负载为 `stats-int-v1`，切片沿用已建立的单机「问—答—验」内核。实验独立于正式迁移（FM）的 Lease、权威来源与结算路径。

[通用分布式作业契约](distributed-job-contract.md)定义整题、计划和执行实例的关系，以及分片、验收、记账和交接的共同规则。当前采用本地多来宾验证路径。

首个双机切片限定为合法的整数统计输入与正常 LAN 交互。单机边界用例继续作为执行内核回归；节点故障、重试恢复、对抗、经济机制和证明证书留给后续场景。

## 切片对象与流程

| 对象 | 首轮内容 |
|---|---|
| `Question` | 判题规则及其语义版本、RIR 工件摘要、输入摘要、会影响结果的资源上限。以现有规范编码与分域摘要机制派生 `question_id`。 |
| `Answer` | `question_id` 与提交的 `Outcome`。首轮结果包含输出或确定性 trap，以及 `gas_used`。 |
| `Verdict` | 对一次提交给出 `ACCEPT` 或 `REJECT`，拒绝附原因。裁决若独立记录，绑定 `question_id` 与答案内容摘要。 |

- **Ask** 接收规则、工件、输入与上限。超出支持范围时拒绝，合法时返回冻结的 `Question`。首轮规则是按固定的候选 RIR 语义执行并精确比较 `Outcome`。
- **Solve** 接收冻结的问题及相应字节，提交 `Answer`。首轮用现有 Python 求值器生成结果，提交者可自行选择求解方式。
- **Verify** 接收冻结的问题、工件和输入字节及一份答案。先核对问题绑定与字节摘要，再由独立 Rust 入口从题目数据求出规范结果，精确比较 `Outcome` 的规范编码。每份提交独立判定。正确的确定性 trap 也可得到 `ACCEPT`。

闭环入口见[最简验证机实验](../../experiments/aclt-minimal-verifier-baseline/README.md)。阶段 2 的[语义与向量](../../experiments/aclt-minimal-verifier-baseline/SEMANTICS.md)固定了计量边界与单侧偏差测试，本地复查使用 `make test-minimal-verifier`。

## 本地内核验收

1. **闭环与对拍。** `stats-int-v1` 和小程序走完 `Ask → Solve → Verify`。Python 与 Rust 对同一组向量产出的规范结果字节一致。
2. **语义边界。** 手算向量覆盖正常输出、除零指令 gas 恰好够时的除零 trap、差 1 gas 时的 gas 耗尽 trap。正确提交均得到 `ACCEPT`。超出支持范围的题目在 Ask 阶段拒绝。
3. **拒绝路径。** 分别改动输出、trap 原因或 `gas_used`，以及将原提交交给另一道题，均得到 `REJECT`。替换传给 Verify 的工件或输入字节时，摘要检查拒绝。
4. **差异检测。** 人为改动一侧的计量规则，固定向量须检出预期分歧，保留对应向量与结果字节。

## 可信双机验收

2026-11-12 起暂时暂停新增物理双机运行。当前按 [ENV-1 本地多虚拟机路径](../08-governance/environment-standard.md#本地多虚拟机验证2026-11-12)验证作业流程，报告注明来宾数量与共享宿主条件。以下物理双机条件继续用于相应物理证据。

本地双来宾路径已首轮跑通：平坦两片、显式预算两片与树归并三片全部通过两端校验，归并输出与单机参照逐字节一致，见[本地双来宾验证第 1 轮](../testing/MULTIVM-20261112.md)。该结果只覆盖来宾级协议与角色切分，物理主机分离由下列物理双机条件单独验证。

### 分工与数据流

1. **请求与拆分。** A 接收原始工件与完整输入，按原统计分块边界拆成至少两个非空、互不重叠且完整覆盖输入的连续切片。只允许最后一个统计块不足一块。计划固定原始工件和输入摘要、归并规则、切片顺序与区间、每片 `question_id`。切片输入保留原分块大小，头部元素数按切片实际长度生成。
2. **派发与执行。** A 和 B 分别计算不同切片，每台机器至少承担一片。A 把分配给 B 的题目和输入通过 LAN 发给 B。执行者用 `Solve` 返回绑定该题的 `Answer`。
3. **交叉验证。** 每份提交由另一台机器用独立 Rust 执行器 `Verify`。验证者获得冻结的题目及对应的工件和输入。题目、提交与裁决在两台机器之间经 LAN 传递，A 汇总裁决。
4. **归并。** A 核对切片区间覆盖、题目绑定和每片裁决。只有所有预定切片各有一份被接受的 `OK` 结果时，才按计划顺序归并。用切片的原始元素偏移与起始行号恢复统计行的全局坐标。每片的 `gas_used` 随本片结果保留，归并产物是全局输出字节。缺片、重复计入、跨片错绑或未通过的切片都不能生成完整输出。

实验入口与整题资源语义的反例见[双机作业切片](../../experiments/aclt-minimal-verifier-baseline/DISTRIBUTED.md)。[分片 gas 分配](../../experiments/aclt-minimal-verifier-baseline/GAS-ALLOCATION.md)记录正常执行路径的成本推导与派发前检查。

### 完成条件

- **物理双机执行。** 按 [DUALHOST-SSH-1](../08-governance/dualhost-ssh-validation.md) 使用两台物理机与独立运行目录。SSH 用于部署、控制和回收证据。作业的题目、输入、提交与裁决走真实 LAN 连接。
- **可核对的归并。** 首个用例用分块大小 2 和输入 `[3, -1, 5, 8, -2]`，A 计算 `[0, 2)`，B 计算 `[2, 5)`，覆盖多片和末尾不足一块。归并输出与完整输入的单次参考运行输出逐字节一致。调换返回顺序仍得到相同输出。用漏片和错绑提交验证归并前置条件。
- **可复查的分工证据。** 保存源码版本、部署拓扑、每片的计划区间和摘要、执行主机与验证主机、裁决及归并输出摘要。日志能复查 A 和 B 分别执行了哪些切片，以及每片在哪台机器完成验证。

[广度优先拆分与递归归并](../../experiments/aclt-minimal-verifier-baseline/TREE.md)用同一组叶子核对不等深计划、结果顺序和叶子费用。

## 乌托邦基线闭合条件

维护者于 2026-11-14 确认以下五项为乌托邦基线的闭合条件。五项同时满足，乌托邦基线才算闭合。闭合只说明可信环境下的分布式作业骨架成立，不代表任何 Gate 退出、OQ 关闭、P0-1B 关闭或生产就绪。

| 条件 | 2026-11-14 状态 | 证据或后续条目 |
|---|---|---|
| 本地内核验收 1–4（闭环、语义边界、拒绝路径、差异检测） | 已满足 | [语义验收](../../experiments/aclt-minimal-verifier-baseline/SEMANTICS.md)；`make test-minimal-verifier` |
| 通用契约 §6 最小跨面验收 | 部分满足，仅来宾级 | [联合验收报告](../testing/MULTIVM-GENERAL-JOB-20261113.md)覆盖两种合法顺序、树形与平铺计划身份、补算记账、预算不足停止和串行交接；同宿主三来宾，不是物理故障域分离。仍缺两个子项，归入条目 M9：其一，计划改为平铺后，按新槽位重新核对并复用已有证据的正例（现有证据中两种计划各自全部重算，回归只覆盖错绑拒绝）；其二，同时存在两个写者时停止（现有交接由宿主先停旧来宾，属于串行交接） |
| 物理双机完成条件（本文[可信双机验收](#完成条件)） | 已满足 | [M3 物理双机基线验收](../testing/DUALHOST-BASELINE-20261114.md)覆盖首个用例的两种 LAN 返回顺序及与整题参照的逐字节对照。漏片和错绑均由实跑证据离线重放并被拒绝。 |
| 一项超出单节点资源的负载在通用契约下被验收 | 已满足（来宾级证据） | [多来宾容量排序通用契约验收](../testing/MULTIVM-SORT-CONTRACT-20261114.md)在同宿主上以单来宾实际交付失败为对照，由三来宾经共享尝试账、接纳与协调器交接发布两片合计 8 MiB 的固定排序结果。 |

## 开工顺序与证据边界

1. **阶段 1–2。** 完成单机闭环、语义与固定向量验收。继续复用现有规范编码、内容寻址、Python 求值器与 Rust 独立执行器。
2. **阶段 3。** 在可信多机环境验证拆分、派发、执行、交叉验证与归并。当前在本地多来宾上按[通用作业契约](distributed-job-contract.md#6-最小跨面验收)推进联合验收。物理双机证据按上节条件单独取得。单机继续覆盖空输入、输出超限、规则版本不符等切片边界。
3. **乌托邦基线[闭合](#乌托邦基线闭合条件)后。** 按可复现的场景推进故障与恢复，并评估轨迹证书对逐步复核、分歧定位和验证成本的影响。[ADR-0009 草案](../05-decisions/ADR-0009-proof-verified-computation-statements.md)可供参考。

实验关联 OQ-02、OQ-04、OQ-05 与 OQ-06，见[未决问题](open-questions.md)。实验验收以本文条件为限。协议语义、ADR 状态、V1 处置及 Gate 结论由各自的权威入口决定。
