## 已接受的决定

1. **接纳事实来自单一权威。** 结果接纳在一个可重放事务中验证签名、身份、Receipt、Profile、Assignment、epoch、intent 和 CONSUME 绑定，检查接纳后的成本及资金用途，并提交事件和投影。以权威单调时钟记录验证通过时刻，严格要求 `received_at < deadline` 且接纳后的成本不超过授权上限。事件父链提供因果序，`ResolveBoundary` 负责合法资金与期限边界之间的选择。恢复时即使期限事件尚未落盘，也须按可信时间检查。时钟回退、来源不可判定或证明缺失时拒绝接纳，并按显式求值规则处理失效事实。
2. **audit 使用无 EligibilitySnapshot 的显式阶段路径。** 首次重执行入口是 `RUNNING` 的分界，须绑定可验证的启动事实。首份 AUDITOR 结果只是后续观察，CONSUME 证明授权已消费。启动状态无法判定时保留已消费事实，禁止自动重执行，无法完成假设求值时走 `INVALIDATING`。候选路径覆盖验证前进入运行、运行内推进及两种阶段到终态的转换。统计字段按方法存在，audit 省略总体、抽样与冻结统计字段。Direct/Proof 起点沿用各自的方法定义。
3. **无 claim 用省略键表示。** audit 方法省略 `verified_claim_spec`，其余方法按各自规范校验该字段。候选迁移同步明确不适用的参数块、ContentMap、Schema View、摘要域与正负向量。以新候选版本和新签名 Receipt 承载变更，保留 S3a 原向量、合约和旧证据的复核入口。
4. **首份合法结果保留计费资格。** 履约槽位绑定 genesis、Receipt、角色、Assignment 和 epoch。相同规范结果重传返回原接纳结果，独立于传输 nonce。异内容拒绝替换首份，冲突证据按冻结上限留存。终态前的验证影响由显式求值决定，已提交终态和权利具有不可变性。费用由唯一终态与冻结政策派生，首版采用原政策，存储投影固定为 `MISSING`，保留完整费用表。HostFault 自签报告只提供已认证的自述事实，结果与报告的竞争规则须在接纳合约中固定，并保证同一槽位至多形成一份履约权。
5. **非主网声明与主网 MAP 分型。** 首轮测试声明仅启用 audit-only，绑定独立 network/genesis、带外信任根、有效期与撤销规则、允许的组件和来源、预算、时钟及提交生效点。候选路径可沿现有测试 pin 开发。正式 CreateReceipt 和各相位接口须完成联合类型、引用与摘要迁移，以及独立准入审查。当前限制作用于本轮部署，未来任务族的方法处置另行决定。

## 实施与验收

- **S3b 第一部分**固定新候选字节、启动事实的来源 contract、时钟和接纳成本定义、HostFault 槽位规则与冲突预算。实现权威接纳、幂等、因果事件和认证快照。测试期限等值、验证耗时跨界、恢复时缺少期限事件、预算边界、重传和冲突竞争。
- **S3b 第二部分**完成 AssumptionEvaluation、方法重放、边界及执行闭合检查和唯一终态提交。期限触发闭合检查，`EXECUTION_FAILED` 须有受认可的 closure 来源、耗尽事件及零有效候选计数。覆盖首次重执行后无结果、启动未知、期间撤销、缺失来源及终态竞争。
- **S3c**从已提交终态和冻结政策派生分项权利与退款。校验 INV-07、重复请求返回原权利、资金守恒和 COMMIT 中断后的查询恢复。集成和故障证据按 [DUALHOST-SSH-1](../08-governance/dualhost-ssh-validation.md) 采集。

各阶段的精确字段、来源 contract、版本、向量与验收证据在对应切片交付。正式规范修订清单覆盖 §3.1/ContentMap/§17、§8.4/§13 Phase B、§9.2 RI-6 与各相位信封，以及 §11.3/SV-112/SV-121 的接纳和闭合验证。正式规则实现、部署准入及 Gate 各有独立验收记录。
