## 1. 这是什么

一份可复核的源码与证据快照，用于：

- 阅读和评审 ACLt Protocol v0.5 规范、ADR 和研究文档；
- 在自己的环境运行本地回归、模型对拍和交付校验；
- 在两台自有物理机上重跑候选 FM-S3 audit-only 链路，并离线复核公开证据。

它不是：

- **不是协议版本**：预览名称 `preview-20261106` 不是 ProtocolVersion（当前语义基线仍为 v0.5），也不是 V1 ConformanceTarget，两者见 [ADR-0003](../05-decisions/ADR-0003-separate-semantic-status-and-version-disposition.md)；
- **不是可部署的软件**：没有可部署的节点、服务或面向用户的 CLI，不能加入网络或提交真实任务；
- **不代表任何验收**：不代表任何 Gate 退出、conformance、正式接口准入、生产就绪或主网可用。

按 [ENV-1](../08-governance/environment-standard.md)：

- **系统**：Ubuntu 26.04.1 LTS，x86_64；
- **Python**：CPython 3.14.4，Unicode 数据库 16.0.0；

预检遇到范围外版本会明确拒绝。其他发行版、macOS、Windows、WSL2、容器和 ARM 均未验收。在这些环境下的失败记录同样是有价值的反馈，请完整提交。

## 4. 快速开始

把源码包解包到一个新的空目录，从包根目录运行：

```bash
make check
```

基线上的实测：22 组、449 项 unittest 通过，约 1 分钟。`make check` 不联网、不编译、不启动 VM，但需要系统 OpenSSL。

```bash
make test
```

`make test` 额外构建 Rust/C++，运行 sanitizer、跨语言编码对拍、回环网络与独立 RIR 入口，需要本地 socket 权限。受 ptrace 限制的沙箱中 LeakSanitizer 可能失败，此时请保留失败日志并换到支持检测的环境，不要移除检测项。

`make verify-source` 需要带完整历史的 Git checkout。在解包目录中它会因找不到 Git 仓库而失败，这符合设计；`make check` 在解包目录中把 Git 源码维度报告为 `NOT_RUN`。

## 5. 双物理机复现（可选）

需要两台物理主机 A、B，从 A 用 SSH 免密登录 B，并严格校验主机密钥。不要关闭主机密钥检查，也不要用同一台机器上的两个目录、VM 或容器冒充 B。约定见 [DUALHOST-SSH-1](../08-governance/dualhost-ssh-validation.md)。

```bash
python3 -B scripts/fm-s3-dualhost.py --peer <B_USER>@<B_IP> --a-host <A_IP> --remote-root /tmp/fm-s3-<NEW_RUN> --output <NEW_LOCAL_DIR>
```

加 `--task-trap` 可改用固定的除零工件：

```bash
python3 -B scripts/fm-s3-dualhost.py --peer <B_USER>@<B_IP> --a-host <A_IP> --remote-root /tmp/fm-s3-trap-<NEW_RUN> --output <NEW_TRAP_DIR> --task-trap
```

- **部署方式**：脚本向 B 上传源码并核对摘要，A/B 各自用系统 rustc 构建执行器并比对摘要。
- **主机分工**：A 承载权威与审计者，B 承载执行者。
- **运行目录**：两端都必须使用新目录。
- **期望结果**：8 个场景通过，两端重放 39 个事件，链头与状态摘要一致，测试账本 68 = 可用 39 + 已分配 29 + 预留 0。
- **离线复核**：用 `scripts/check-fm-s2-evidence.py --s3b` 和带外保存的 genesis、anchor pin 复核公开归档，见 [FM-S3 收尾](../testing/FM-S3-CLOSEOUT-20261106.md#复现)。

## 7. 已知限制

- **候选路径而非正式路径**：正式接口验收 `OPEN`，`official_admission: false`；只实现 audit-only 方法。`DIRECT_VERIFIED`、`PROOF_VERIFIED` 和 `REEXEC_BOUNDED` 不在候选路径内，B/Q 未建立。
- **终态覆盖不全**：候选路径只能到达 UNRESOLVED 和 EXPIRED，trap 一致时得到 CONCORDANT/UNRESOLVED。执行闭合（`EXECUTION_FAILED`）和可耗尽预算（`FUNDING_EXHAUSTED`）尚不可达，费用矩阵中对应的行没有实跑证据。
- **信任假设**：
  - 首次重执行的启动事实是 Provider 的自签声明，不是权威可观测的事实；
  - 测试时钟由操作者提供；
  - 审计者与权威同在 A 上，属于同一故障域；
  - 只有单一可信权威，权威自身的回滚不受保护；
  - 进程终止不等同于整机断电。
- **测试资产**：只使用测试身份、测试签名和整数测试账本，不涉及真实资金或真实付款。
- **故障矩阵**：FM-S3 只重跑了 8 个场景，尚未与 Work 2/3 历史的 12/12/14 场景逐项对照。
- **平台与来源**：只验收了第 3 节列出的环境；发布来源只有 SHA，没有签名根；公开证据作为附件单独提供。
- **历史证据**：部分历史日志含维护者的主机名和本地路径，按"保留历史证据"原则未改写。
- **许可与名称**：代码采用 Apache-2.0；规范、文档、名称和商标的许可尚未决定。ACLt 的名称与软件包名清查仍为 `OPEN`。
