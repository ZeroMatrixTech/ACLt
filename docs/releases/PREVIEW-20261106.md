## 1. 这是什么

这次公开发行提供 ACLt Protocol 仓库在公开时点的源码与证据快照，用于公开评审、复现和后续实现参考。可用的场景包括：

- 阅读和评审 ACLt Protocol v0.5 规范、ADR 和研究文档；
- 在本地环境运行回归、模型对拍和交付校验；
- 在两台自有物理机上重跑最简验证机、容量排序和 R2 多来宾链路，并离线复核公开证据。

发行定位有三条边界：

- **协议版本分离**：发行名称 `research-preview-1` 不是 ProtocolVersion（当前语义基线仍为 v0.5），也不是 V1 ConformanceTarget；两者见 [ADR-0003](../05-decisions/ADR-0003-separate-semantic-status-and-version-disposition.md)；
- **非可部署软件**：仓库没有可部署的节点、服务或面向用户的 CLI，不能加入网络或提交真实任务；
- **验收边界**：本发行不构成任何 Gate 退出、conformance、正式接口准入、生产就绪或主网可用的证据。

仓库转为公开和打发行标签是两个动作：前者让本文可被公开阅读，后者才使 `research-preview-1` 成为一个已发布快照。第 10 节的清单按这两个动作分段。

## 3. 环境要求

按 [ENV-1](../08-governance/environment-standard.md)：

- **系统**：Ubuntu 26.04.1 LTS，x86_64；
- **Python**：CPython 3.14.4，Unicode 数据库 16.0.0；
- **编译器与工具**：Rust/Cargo 1.93.1、G++ 15.2.0、GNU Make、Bash 5.3.9、OpenSSL 3.5.5；
- **文件系统**：本地文件系统，需支持文件锁、硬链接、原子重命名和 fsync。

预检遇到范围外版本会明确拒绝。其他发行版、macOS、Windows、WSL2、容器和 ARM 均未验收；这些环境下的失败记录同样构成有价值的反馈，提交时附完整日志。

## 4. 快速开始

把源码包解包到一个新的空目录，从包根目录运行：

```bash
make check
```

2026-11-15 在 `155a752` 上的实测：`make check` 默认 23 组 648 项 unittest 通过，退出码 0。`make check` 不联网、不编译、不启动 VM，但需要系统 OpenSSL。发布前在发布 commit 上重测，最终计数记录在 GitHub Release，本文不回填。

```bash
make test
```

`make test` 额外构建 Rust/C++，运行 sanitizer、跨语言编码与 Profile R1–R11 对拍、回环网络、独立 RIR 入口，并完整重放公开快照，需要本地 socket 权限。2026-11-15 在 `155a752` 上的实测：25 组 765 项 unittest 通过，退出码 0。最终发布 commit 的计数记录在 GitHub Release，本文不回填。受 ptrace 限制的沙箱中 LeakSanitizer 可能失败；此时保留失败日志，并在支持检测的环境中重跑，移除检测项的运行不计为通过。

`make verify-source` 需要带完整历史的 Git checkout。在解包目录中它会因找不到 Git 仓库而失败，这符合设计；`make check` 在解包目录中把 Git 源码维度报告为 `NOT_RUN`。

## 5. 双物理机复现（可选）

需要两台物理主机 A、B：从 A 用 SSH 登录 B，并严格校验主机密钥；关闭主机密钥检查，或以同一台机器上的两个目录、VM、容器代替 B 的运行，都不属于双物理机证据。约定见 [DUALHOST-SSH-1](../08-governance/dualhost-ssh-validation.md)；每轮只做一次故障注入，并在运行前取得主机锁。

| 容量排序 | 8 MiB 固定记录、两个 4 MiB 分区、跨机求解与重放 | [容量排序](../testing/DUALHOST-CAPACITY-SORT-20261114.md) |

M3 入口（普通顺序）：

```bash
tool=experiments/aclt-minimal-verifier-baseline/dualhost.py
flock "${XDG_RUNTIME_DIR:-/tmp}/aclt-experiment.lock" \
  python3 -B "$tool" run --peer "$B_PEER" --remote-root "$B_RUN" --output "$LIVE"
python3 -B "$tool" replay-baseline "$LIVE" "$LIVE/executor" "$REPLAY"
```

重跑时给 `run` 和 `replay-baseline` 都加上 `--reverse-schedule`，可重跑反向 LAN 顺序。期望：两端构建的执行器摘要一致，A 求解 `[0,2)` 由 B 复核、B 求解 `[2,5)` 由 A 复核，归并结果与单机逐字节一致；缺失切片和错误绑定被拒绝。

容量排序入口：

```bash
entry=experiments/aclt-minimal-verifier-baseline/capacity_sort.py
python3 -B "$entry" serve --output B --address "$B_IP" --source "$A_IP" --port 0 --nonce "$NONCE"
python3 -B "$entry" connect --output A --address "$B_IP" --source "$A_IP" --port "$PORT" --nonce "$NONCE"
python3 -B "$entry" replay A B
```

期望：单机无法完成第二个 4 MiB 分区，双机完成并重放成功；删除或替换分区字节会被拒绝。

R2 入口：

```bash
python3 -B experiments/aclt-minimal-verifier-baseline/multivm.py run \
  --kernel "$KERNEL" --output "$NEW_DIR" --guests 3 --leaves 3 \
  --dualhost-config "$PRIVATE_JSON" --host-b-roles B \
  --solve-budget 34768 --interrupt drop-reply SOLVE-1 --retry-solve
python3 -B experiments/aclt-minimal-verifier-baseline/multivm.py replay \
  --evidence "$RUN_DIR" --executor "$MATCHING_EXECUTOR"
```

双机入口会同时取得两台主机的锁。正常发布时退出 0；发生可验证的安全停止时退出 1；设置或证据失败时退出 2。重放在可验证的发布或安全停止时退出 0，否则退出 2。

R4 已完成，见 [R4 报告](../testing/R4-SAFETY-MC-20261116.md)：按 [R1 规格](../07-roadmap/first-public-release-safety-plan.md)（含修订 1）在双机多 VM 上运行安全层蒙特卡洛，每个 pass 32 个带种子运行、违反 0 次、可复现；不报告概率上界或置信度。若要给出概率性结论，须按 #128 先登记统计设计。报告与摘要归档在仓库内，链接与摘要记录在 GitHub Release。公开证据包不含执行器二进制（其中嵌有本机构建路径），只记录其摘要，因此外部复核者可以校验清单，但还不能完整重放检查。

## 7. 已知限制

- **候选路径而非正式路径**：正式接口验收 `OPEN`，`official_admission: false`；当前实现只覆盖 audit-only 方法。`DIRECT_VERIFIED`、`PROOF_VERIFIED` 和 `REEXEC_BOUNDED` 不在候选路径内，B/Q 未建立。
- **#101：无许可与独立性边界**：“无许可”是设计目标，不是当前已实现属性。现有实验使用固定协调器、固定角色与固定对端地址；同宿主多 VM 证据只支持来宾级结论；物理故障域分离、无许可协调与统计独立性尚未建立。
- **#101：记账推广边界**：求解、复核、通信、归并和失败尝试的成本已分别记录，但不同任务复杂度与故障率下的占优范围尚未测量；单组参数的结果只在该参数组合下成立，不构成通用结论。
- **终态覆盖有界**：四个过程终态都可达，但 `FAILED` 依赖合约钉住的测试观察方密钥，不是正式闭合来源；`FUNDING_EXHAUSTED` 只在首次激活冻结之前可达，过程中按用量耗尽未建模。
- **信任假设**：启动事实是 Provider 签署的已核验入口描述，只证明签署了确切调用，不证明运行时已执行；旧合约仍为自签声明。测试时钟由操作者提供。审计者、闭合观察方密钥与权威同在 A 上，属于同一故障域。只有单一可信权威，权威自身的回滚不受保护。进程终止不等同于整机断电。
- **测试资产**：只使用测试身份、测试签名和整数测试账本，不涉及真实资金或真实付款。
- **故障矩阵**：Work 2/3 的 38 个历史场景已逐项对照；FM-S3 结算路径未单独重跑 gas 耗尽型 trap。
- **安全层统计**：安全层蒙特卡洛驱动（R3，#140）已合入；R4 已完成（[报告](../testing/R4-SAFETY-MC-20261116.md)），只报告“每个 pass 32 个带种子运行、违反 0 次、可复现”，不报告违反概率、置信区间或上界。0 次违反不是安全概率的估计，安全层 0 违反也不等于全系统安全；如需概率结论，须按 #128 单独登记统计设计。
- **平台与来源**：只验收了第 3 节列出的环境；发布来源只有 SHA，没有签名根；随包公开证据的 genesis/checkpoint 仍需从留存报告或审查过的仓库版本取得可信来源。
- **签名**：截至起草时，随仓库公开的证据标签未签名，本次发布也没有既有发布签名；仓库没有发布签名根。发布标签建议签名，但签名本身不建立外部信任根；若发布时未签名，Release 页面必须明示。
- **历史证据**：按 2026-11-15 维护者决定保留并公开；部分历史日志含维护者的主机名和本地路径，未改写。

## 8. 适用范围与表述边界

本发行是研究预览，适用范围与表述边界如下：

- 协议版本：`research-preview-1` 不是 ACLt 协议版本，也不是 V1 conformance；ProtocolVersion 仍为 v0.5；
