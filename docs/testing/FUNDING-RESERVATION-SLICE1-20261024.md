## 冻结对象与账务权威

本轮只有预置整数测试资产 `aclt.exp.test-unit@1`，精度 0，不使用真实资金。测试 genesis 一次明确预置余额；运行中无充值、发行、信用额度或转账入口。金额必须为 0..2^63-1 的整数，预留 cap 为正，固定成功费用不超过 cap，初始总量不超过该整数上限。浮点、负数、bool、其他资产/来源与溢出拒绝。

专用 `aclt.exp.funding-policy@1` 冻结任务身份、Requester/收款引用、测试资产/精度、资金来源、authorized cap、固定成功费用以及结算/退款/待定规则 ID。FREEZE 同时核对原始任务承诺、工件和输入，Requester 必须与任务承诺及已认证付款账户一致；policy ID 使用独立实验哈希域，不修改原任务承诺或伪造 ReceiptID。

规则预承诺“后续有效精确比较决定可按固定费用付款并退余款”“有效关闭且无需付款时全退”“未知状态继续占用”。本轮不实现这些决定或付款/退款转移；规则 ID 不替代正式终态×故障归因×资金来源矩阵，不关闭 OQ-10。ACCEPT、Task OK、超时或宿主故障均不自动产生付款或退款依据。

A 的单一可信 SQLite 账本/服务是本轮资金权威，B 是认证请求端；B 本片不运行 guest。HMAC 是实验账户 enrollment，引用不是正式身份控制证明。签名回执/回复复用已有 OpenSSL RSA-2048/SHA-256 适配，不新增协议 Principal 或生产结算裁判。

## 原子预留与幂等

1. FREEZE 只固定政策，不移动余额、不授权执行。同一部署中一个实验任务只接受一份政策；相同字节幂等，改变 cap、费用或收款方冲突，原政策不被覆盖。
2. RESERVE 只接受 policy_id，从冻结政策派生完整 cap，调用方不能另传金额。认证付款方必须匹配；未知政策/其他付款方拒绝。
3. `BEGIN IMMEDIATE` 下检查可用余额，并在同一事务完成 available→reserved、唯一预留、首次签名回执和追加事件。余额不足不部分扣款、不透支，是实验创建前资金拒绝，不冒充正式 FUNDING_EXHAUSTED 终态。
4. reservation ID 绑定 deployment 与 policy_id，唯一约束防止新 nonce、同包重放、并发或服务重启产生额外占用。重复 RESERVE 与 STATUS 返回首次保存的同一回执字节。
5. 提交前签名/事件写失败整体回滚；提交后回复失败仍保留预留，查询原状态再恢复。本片不取消占用、自动退款或盲目重试外部付款。

所有状态满足：初始总量 = Σavailable + Σreserved；Σ账户 reserved = Σ唯一预留金额；余额非负，预留金额等于原政策 cap。冻结但未预留的政策不能作为已获资金的执行依据，也不能将多个政策的 cap 总和当成实际预留。本轮两桶投影不是正式 Committed/Settled/RefundReserved 全部账务语义。

**资金预留与执行槽位/暴露额度不同。** 既有执行入口尚不查询本资金账本；下一切片须接入比较/结算依据，并由后续统一准入确保资金冻结/预留在 grant 和调用前成立。此处不声称已为旧入口强制执行“资金先于计算”，预留回执也不是 ExecutionCapability。

## 本轮真实双机证据

固定 **47 个源文件**部署到 B 全新独立目录，A/B 分别使用已有 Python/SQLite/OpenSSL。A 服务与资金账本同一故障域，B 请求经真实 LAN TCP 发送 FREEZE/RESERVE/STATUS/BALANCE；SSH 只部署、控制、取证，严格主机密钥检查保持开启。无 VM、安装、下载、Rust 重编译或 guest 计算，未改防火墙/系统服务。

**12 个场景全部通过：**

| 场景 | 本轮结果 |
|---|---|
| 冻结政策 | 不扣款；原始任务/工件/输入绑定 |
| 正常预留 | 按原政策 cap=100 占用，费用=30 保持冻结 |
| 新 nonce 重传 | 原回执，不重复扣款 |
| 两个 B 进程并发同政策 | 均取原预留，无额外占用 |
| 冻结后修改费用 | CONFLICT，原政策保留 |
| 两个任务各请求 150 竞争余额 | 恰好一个 RESERVED，另一个 INSUFFICIENT |
| 剩余 50 时再请求 51 | 不部分预留，不隐式补资 |
| 其他付款方 | DENIED |
| 未知政策 | DENIED |
| A 服务重启后查询及重传 | 原预留与原回执保留 |
| 真实停止服务 | B 失败，无本地账本 fallback |
| 服务恢复后核对余额 | 可用 50、预留 250，总量 300 |

共 4 个冻结政策、2 个唯一预留，预留为 100+150；没有付款/退款，未预留政策不构成新占用。12 场景是状态/请求验证，不是 12 次计算。A 共 **18 条事件**：GENESIS 1、FREEZE 5、RESERVE 10、STATUS 1、BALANCE 1。保存 **17 份 B 原请求/签名回复**，用独立保存的公钥逐一校验 request digest/nonce/op/deployment 和 A 事件决策，回执同原记录一致。

**5 个证据篡改反例全部拒绝**：截断事件、修改投影、修改事件前项、错误 key pin、错误 checkpoint digest。只改副本，原始证据保留。

独立离线 `audit.py` 不导入 Ledger 或其转移函数，从保存事件重建政策、账户和预留，核对原签名回执、守恒以及 signed head/projection。另进程运行其 CLI 得到同样的 **18 条事件、可用 50、预留 250、2 个唯一预留**。它共享 schema/codec/密码学原语；离线不持有 HMAC secret，请求认证的可信来源是签名权威 checkpoint，不能称为第二套独立密码或 enrollment 验证。
