## 精确 suite 与权威边界

RSA-2048/e65537、RSASSA-PKCS1-v1_5/SHA-256，固定 DER SPKI 294 字节及签名 256 字节；tag 长度前缀 + tag + 全部 unsigned envelope 编码作为唯一签名输入。绑定协议/schema/编码版本、principal record 摘要、角色、部署/网络、测试对象类型、调用者上下文、nonce、期限、固定 import 与 payload。摘要/tag 唯一归属在候选合约中列明；无裸 digest 签名或重复 hash 的隐藏选择。

pin、预期上下文及 now 必须由可信调用者显式提供，不能从来件复制后当授权。结构检查模式不等于签名接受；只有 fm-verify 检查 pin/context 与 RSA。相同请求的离线验证幂等通过；新 nonce/context 拒绝旧消息。持久 nonce/业务槽消费仍属 FM-S2/S3，本片不建立至多一次执行/付款。撤销仅能通过带外停止接受旧 pin 表达；不实现在线注册、撤销历史或轮换。日志 signer 不是第三种 Principal。

Python 共用既有 P0-1 core，Rust 共用其独立 Rust core，各自做 raw parsing、类型/集合、Rational/SemVer、有限 ENUM、Schema View 和 SHA。Rust 不调用 Python 预验证；两端共享向量和 Unicode 数据版本不算实现同源。RSA 都调用 OpenSSL，不能宣称两份独立密码学实现。仅 FM 所需 ENUM/固定测试 import 落地，ClaimTemplate ENUM slot、其余官方 imports 与完整五相位对象仍未补齐，不改变 coverage 登记。
