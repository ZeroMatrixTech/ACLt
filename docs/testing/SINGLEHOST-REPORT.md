## 结论与范围

本轮把当前已有实现和本轮新增功能的可执行单机检查跑完，并补了额度、任务绑定、参数边界、畸形输入和跨语言小函数对拍。它不是整个 ACLt 的单机参考实现验收：未实现的协议对象、日志、资金结算和 RIR/RPR 无法靠增加故障脚本变成通过。

测试统计分开报告，不把每次断言或排列展开都算成一个新的协议规则。

|---|---|---|
| 原实验回归 | 68 基础 + 12 进程 + 12 恢复 + 90 批量 + 22 生命周期 | 204 场景通过 |

## 发现并修正的问题

| 原行为 | 修改与验证 |
|---|---|
| 未知 `schema_version` 可以返回无问题 | 明确拒绝未知版本；保留错误输入正反例 |
| 非对象假设条目、错误格式原因项会被跳过 | 拒绝畸形行，不把缺失事实当成 VALID |
| 列表形式的方法、null 假设集合等导致 TypeError | 返回结构化错误；CLI 对坏 JSON、重复键、非标准数值常量、无效编码返回拒绝 |
| 只检查 AUDIT_ONLY 必须是 BOTTOM，没有检查逆方向 | 补齐只有 AUDIT_ONLY 可声明 BOTTOM 的检查 |
| 零权重项也被当成有效支持项，从而拒绝规范允许的表 | 按正权重支持集检查下界，同时保留排序、去重、非负和精确求和检查 |
| 有理数分子没有执行规范中的整数范围 | 增加 int64 边界与过长文本拒绝；不据此宣称完整 CBOR 整数规则已实现 |
| 调度器允许 10000 ms 超时，却传给 worker 一个被拒绝的 20000 ms 测试延迟 | 对齐 worker 延迟范围；正常任务在 5000、5001、10000 ms 边界重新验证 |
| 没有显式累计验证比较、日志与目录额度 | 增加固定额度、先记账再核验、逻辑文件空间预留和直接 worker 输出限制 |
| 正确数字结果可从另一任务挪用；部分参数只在可改快照内 | 增加独立任务约定与任务 ID；修改约定或跨任务结果重放均拒绝 |

前五个原始异常/误放行探针保存在 pre-fix-findings.json；worker 边界修复前记录位于实验目录 docs/worker-boundary-before-fix.json。其他修复以新增正反例验证，不伪造不存在的历史运行日志。

## 对上一轮清单的逐项处理

| 清单 | 本轮证据 | 尚不能外推的部分 |
|---|---|---|
| A 永久结束不能反转 | 原 22 个生命周期场景、新增发布后额度/日志错误场景 | 完整协议终态、取消、结算未实现 |
| B 恢复记录一致 | 原 12 恢复、90 批量与日志异常场景；恢复核验计费 | state.txt 为权威快照；并非事件日志重放、finality 或数据库恢复协议 |
| C 累计上限 | 尝试、恢复、整体期限，以及本轮比较单位、日志/普通文件逻辑字节、worker 输出上限 | 不计解析、哈希、打印、已完成任务的只读复查；没有全 CPU/RSS、磁盘块、inode、外部写入或资金上限 |
| D 固定任务条件 | 输入、程序、分块、规则版本、次数、期限与额度绑定；跨任务重放拒绝 | 本地 contract.txt 无签名；同一用户仍可同时改约定和状态；不是正式 Receipt 或 RIR/RPR |
| E 多原因固定判断 | 全部三种假设原因的子集/排列/重复/未知值；64 组双假设原因组合；Rust/C++ 小函数对拍 | 未把完整 CauseSet、证据引用与五相位信封接入调度器；本地失败原因不能冒充资金边界判决 |

## 文档要求的覆盖账本

逐条编号与状态见 SINGLEHOST-COVERAGE.json，来源是 verification-profile-schema.md §13.2：**119 项 Type A，6 项 Type B**。SV-40 为延期项目，SV-15 已作废，均不算通过或本轮待执行用例。

- 3 项规则按当前登记为已实现并测试：SV-10、SV-11、SV-76。
- 5 项为部分实现并测试：SV-01、SV-30、SV-31、SV-54a、SV-57。
- 其余 111 项 Type A 仍缺对应实现。它们大多可在单机做算法一致性测试，但目前没有可运行的完整校验对象或入口；不能标成“环境不支持”，更不能标为通过。
- SV-57 从“已实现”修正为“部分”：当前函数检查安全假设的判决，但 COMPLETE/INVALIDATING 与完整 Phase D 的接入未完成。此处修正覆盖登记，不是降低安全要求。
- 生产模式仍无条件拒绝。测试中的简化 Profile 和空规则块不可以上线使用。

本轮没有凭有限实验关闭 P0-1B、G2 或任何更高 Gate。

## 仍需补实现，再做单机验收

这些是代码/规则缺口，不是需要购买第二台电脑才能测试：

1. 119 项规则中的未实现部分、完整五相位对象、规范 CBOR、18 个摘要及全量跨语言验证器。
2. RIR/RPR、正式 Receipt/Lease/ExecutionCapability、调度接单协议与权限旁路检查。
3. 正式事件日志提交/重放/最终性适配器；本地辅助日志目前不承担这些职责。
4. 资金、退款、部分履约和结算的处理表与实现；没有账务实现不能宣称验证了不重复付款。
5. 主机整体 CPU/内存/磁盘与任意敌对程序隔离。当前仅计量明确列出的局部资源。

真正需要额外部署或专门环境的证据另列：独立物理节点、真实网络分区和共因故障、物理断电/设备故障、真实参与者独立性和主网运行事实。单机仿真可以准备接口，但不能替代这些证据。
