# R13 Phase D 候选判决独立重放

本轮补齐 [R12 候选编码](PROFILE-PHASE-D-R12-20261109.md)
的 Rust 实现，在同一组已认证的 R11 来源投影上独立重算方法接纳与成本、
截止与资金边界、执行闭合、条件顺序、终态和完整候选 CBOR；A/B 两端 17 条候选记录
逐字节匹配、21 个负例均按预期原因拒绝，完整 `make test` 通过 24 组 668 项 Python
测试与 20 次 sanitizer 检查。基线为 main `ad704f8`（R12）；Rust 复用本语言的
R10 接纳、边界和闭合检查，独立生成候选摘要与判决记录，R11 的聚合、条件和
Python 候选字节仅用于核对；历史 R10/R11/R12 摘要和旧归档沿用原值。

输入是 R11 的来源 CBOR、待比较的候选 CBOR，以及外部给定的部署和来源摘要。
本轮由 Python R11 桥接层验证签名、固定检查点及历史结算，再把已认证投影交给
Rust。Rust 检查来源摘要并重新求值。它仍依赖桥接层提供撤销、入口和观察者签名
等来源事实。固定快照复核只读运行。

## 复现

运行 `make test-phase-d-crosscheck`。可用 `PHASE_D_CROSSCHECK_REPORT`
指定尚不存在的报告文件。该目标也包含在 `make test` 中。

- 正例覆盖 R12 冻结的 17 条 Receipt，比较完整候选 CBOR，并核对来源和候选摘要。
- 负例覆盖 R12 的 10 种候选篡改、错误的外部 pin 和截断或附加数据。
- 额外构造使用单独测试 pin 的合成来源。聚合、条件、截止、预算、闭合和日志截点
  与自身来源事实不一致时，Rust 必须在求值阶段拒绝，不能仅靠摘要不匹配拒绝。

## 验收边界

FM-A08 增加候选 Phase D 的跨语言实现证据。正式验收仍需注册 Profile 和来源合约、
Phase B/D 正式信封，以及对正式来源与信封的端到端验证。现有可信时钟、日志终局性和
观察者授权按外部合约处理。正式 FM-A08 保持 `PLANNED_NOT_RUN`，P0-1B 为 80/36/3。

## 双机结果

A/B 通过 SSH 在各自临时目录校验同一源码包的 76 项输入，独立认证历史证据并编译
Rust。两端的 17 条候选记录逐字节匹配，21 个负例均按预期原因拒绝，结果摘要同为
`08bf62e36484e5beab317b8427b586d3a7d852a594e903e43f72b36511dd2b3d`。
其中 7 个负例使用重新固定摘要的合成来源以单独检验语义守卫。
R11 历史重放摘要仍为 `2f244334a7ddfb264d6c16f107cc5c06b1a3229ea6996023a83216cd48dc5c50`。
本轮双机证据来自同一组历史归档的只读组件验证。

[机器可读摘要](PROFILE-PHASE-D-R13-20261110.summary.json)记录源码 pin、工具版本和各负例的拒绝原因。
