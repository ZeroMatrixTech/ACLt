# FM-S2 限定测试集成

日期：2026-10-31；源码基线 main `c596e60`（#63）。执行代码、[候选合约](../../schemas/formal-migration/execution.md)、[机器摘要](FM-S2-20261031.summary.json)同轮交付。只完成限定测试集成，不签发正式协议对象或启用官方准入。

## 本轮结果

从 FM-S1a 的角色签名、FM-S1b 的政策/Receipt 和原始 RIR Rust 核心接通了单一新部署：Requester 创建承诺 → 固定双 Assignment → Provider 签署接受 → 唯一 epoch/Lease + 资金/五维暴露原子预留 → Dispatch 查询 → worker 持久 intent → 同一权威消费唯一 Attempt → Rust 原始工件执行。A 运行权威和 auditor，B 运行 executor；A 权威与 auditor 仍属共同故障域。签名、资金、暴露、幂等记录与事件共用一个事务，不拼接旧两套账本。旧实验保留，其 CHECK/CONSUME、funded-start 等输入不被新部署接受。

实际收口有三次全新物理双机运行，第三轮绑定最终集成源码与各自主机构建的相同 Rust 二进制 SHA。前两轮各 16 场景、最终轮 17 场景 PASS，旧轮保留。最终轮后的公共快照逐条验证原角色签名、事件父引用/摘要、状态 reducer、资金守恒及最终投影，并核对 B 独立保留的 checkpoint。最终 17 份公共快照共重放 60 条事件，17 个 B 锚点均验证。确切 hash、场景/事件计数在机器摘要中；不能把摘要当作第三方审计、物理/统计独立证明或权威抗回滚证明。

| 场景 | 已检查的性质 |
|---|---|
| 正常双端执行 | Provider 接受分别签署，A/B Rust raw-artifact 结果字节/摘要相同；再次运行 B worker 返回已保存观察 |
| 完全相同激活重传 | 返回原 Lease，不重复预留 |
| 旧 epoch、错 capability、错签名 | 拒绝且资金/暴露/nonce/事件状态不变 |
| 旧 CHECK/funded-start/START/SETTLE | 不存在兼容启动或结算旁路 |
| 两个并发 CONSUME | 两份真实 Provider 签署的 intent 通过 LAN 竞争，只有一份被接受 |
| 暴露超限 | Provider/共同池额度占满后，第三个 Receipt 激活被拒；不额外占资金 |
| 激活回复丢失 | COMMIT 后关闭真实 TCP 响应，查询/原请求重传只取原授权 |
| CONSUME 回复丢失 | 消费已提交但真实回复丢失；worker 保留 UNKNOWN，首次与恢复均无 guest 调用 |
| COMMIT 前后中断 | 服务进程在真实事务边界直接退出，恢复后预留分别未提交/已提交且不重复 |
| worker intent/consume/guest 后中断 | 真实 worker 进程退出；原目录恢复保留 UNKNOWN，不新调用 guest |
| 权威不可达 | 服务停止时不离线执行；不修改管理 SSH 或系统网络 |
| deadline | 权威逻辑时钟到期后拒绝启动，FENCE 幂等释放暴露，资金留待 FM-S3 |

上述合并表对应 17 个命名场景，不是把 Work 2/3 的全部提交、结果、结算和恢复矩阵提前宣告完成。后者仍由 FM-S3 以新对象重跑。并发、五种暴露维度、资金不足、nonce 冲突、旧部署/未知字段、期限/时钟回退、日志投影篡改、错 issuer、响应时间、公开离线快照与固定向量另有 17 个默认单元方法（子例数不冒充方法数）。14 条公开向量覆盖连续正向迁移、完全相同重传、旧 epoch、错能力、重复消费、错误责任、旧 schema/启动旁路、未知字段及 CBOR 非规范编码。私钥未写入源码包。

## 证据与复核入口

本地产物 `<EVIDENCE_ROOT>/fm-s2-20261031/` 保留三轮部署命令/退出码、源码 SHA、两端构建日志、原始 request/response、B worker journal、SQLite/热日志、运行配置、公钥、公共快照与失败开发日志。生成私钥只在各轮 private 目录；B 仅收到 executor 私钥，issuer/Requester/auditor 私钥留 A；公共 B 证据归档排除 executor.pem。没有软件安装、VM、系统服务/防火墙更改或真实支付。

最终 `make test` 退出 0：默认 376 项（359 + 17），Claim 29766、FM-S1a 179、FM-S1b 196、RIR 核心 161 项对拍及 20 次 sanitizer 均通过。生成最终摘要时曾与清单检查并行而出现清单过期失败；原日志保留，固定摘要并刷新清单后全量重跑通过。开发期导入/字段比较失败与早期 ResourceWarning 同样保留，最终日志无该警告。

默认 `make check-fm-s2` 不联网；全量 `make test` 保留旧回归、两语言 FM/RIR 对拍与 sanitizer。显式 `make test-fm-s2 FM_S2_PEER=user@B FM_S2_A_HOST=A_LAN_IP FM_S2_REMOTE_ROOT=/new/B/path FM_S2_OUTPUT=/new/A/path` 才新建双机矩阵。保持严格 SSH known_hosts，输出/远端目录须不存在，旧证据不会覆盖。

只读公共快照复核：

```sh
python3 -B scripts/check-fm-s2-evidence.py \
  --config /retained/public-config.cbor --snapshot /retained/snapshot.cbor \
  --expected-genesis EXTERNALLY_SAVED_GENESIS_HEX --anchor /retained/B-anchor.cbor
```

省略 anchor 只验证相对于带外 genesis 的内部一致性，不能证明新鲜性。旧的合法签名不足以证明最新事实；未知、丢回复和客户端文件都不能生成新权利。

## 明确保留的门槛

本轮使用固定测试时钟（3000；期限场景 5000）注入 deadline，非真实墙钟活性保证。SQLite 单权威不回滚、带外 pin、诚实 pinned host 和共享 LAN 是接受的有限测试假设。公开签名检查不是独立密码学实现。

Receipt 中的 sandbox 声明尚未得到完整 OS sandbox 验收；测试 Runtime 组件明确声明 honest pinned test host。有限 allowlist/原始 Rust validator 不能冒充完整 RPR、全部七阶段优先级、恶意 worker 隔离或正式对象语义。没有新增通用 Phase B/EligibilitySnapshot/非主网 assurance 表达；四项接口审查保持 OPEN。

消费或相同结果均不是履约/终态/付款依据。FENCE 只终止本测试授权与暴露，不创建 VerificationDecision、EXPIRED 或退款权；即使期限到达，已占测试资金仍留在原部署，等待 FM-S3 的正确终态、费用政策和权利处理，不能用新 genesis 抹掉它们。无 ResultSubmission、AssumptionEvaluation、TRUSTED、费用结算或自动 guest 重试。

P0-1B 3/19/97、ADR-0006 具体规则 PROPOSED、OQ/Gate/V1 处置均不改变。下一主线是 FM-S3 的限定 audit-only 证据/判决/账务集成；先解决实际触及的接口表达，保留完整正式准入门槛。
