# 最简验证机 · 双物理机容量受限排序

2026-11-14，经维护者恢复授权，按 ENV-1 和 DUALHOST-SSH-1 在两台物理机上运行固定容量交付实验。双节点各持一张 6 MiB 镜像完成 8 MiB 交付，离线逐条重放通过；单节点对照在第二分区写入时出现块分配失败，缺失和单字节替换均被重放拒绝。固定源码 `58b3022f4a35aaa456818659dbcd15fb1f879d2c`，两端校验同一 91 项源码清单。两端均为 Linux 7.0.0-43-generic x86_64、Python 3.14.4、e2fsprogs 1.47.2。SSH 保持严格主机密钥校验，仅用于部署、启动和回收证据。输入和产物分区通过两端直连 LAN TCP 交换，双方 socket 记录方向相符。

## 固定交付条件

整题要求按 `(key, ordinal)` 升序完整交付 524288 条固定 16 字节记录，共 8 MiB。原始输入分为两半，每半分别在一个节点生成，含重复键和分区边界值。两主机分别按键范围交换记录，各自计算、写入并重读一个 4 MiB 分区，再交换从各自镜像重读的产物并相互验证。验证检查每个序号唯一、记录与冻结输入一致、位于正确范围、顺序正确，且分区记录数等于该范围的完整人口。两个键范围互斥且有序，因此按清单顺序读取两个分区得到整题结果。

每节点仅有一张允许用于交付的 6 MiB 固定长度 ext4 镜像，格式化后可用数据块为 5857280 字节。实验使用普通用户态工具写镜像，无需调整系统磁盘配额。每次只在内存中处理有限分区，交付条件要求最终的完整、固定编码记录驻留于指定镜像。协调器只发布绑定声明、计划、执行实例和分区摘要的清单，完整数据仍驻留在两端镜像。

| 验收场景 | 结果 |
|---|---|
| 单节点，单镜像 | 第一分区可复核，第二分区写入出现文件系统块分配失败。残缺文件表观长度仍为 4 MiB，重读核验失败。 |
| 双节点，每节点一张同规格镜像 | 两个 4 MiB 分区均写入并重读交叉验证，共 8 MiB；发布清单，离线逐条重放通过。 |
| 保持清单，删除 B 分区 | 重放拒绝，报告产物缺失或截断。 |
| 保持清单，替换 B 分区内一个字节 | 重放拒绝，报告记录与冻结输入或范围不符。 |

分区摘要依次为 `6b5c9c27b69556f21467cbaee33d754f233b955bbb48f8f00364d791610547f9` 与 `224925948b188bc024e6b418cc7619d611183a7668a1cd487253347d050eea15`。按协议，成功运行时每端在两次分区交换中发送和接收的应用层净荷各为 6291456 字节，由 2 MiB 的初始输入交换和 4 MiB 的复核交换组成。这个数由协议构造决定：发送端按固定大小分帧发出，接收端逐帧校验长度（`capacity_sort.py` 的 `move_out`、`move_in`）。运行时没有单独计数，`result.json` 中的 `payload_sent`、`payload_received` 是按同一构造写入的常量；数值不含分帧头与 TCP 开销，也不含执行绑定握手与验收回执这两类 CBOR 控制消息（`capacity_sort.py` 中 `hello` 与 `verified` 的收发）。

> 2026-11-14 措辞更正（#115，审计 PRA-113-07）：本句原文为“每端发送和接收的数据净荷各 6291456 字节，由 2 MiB 的初始输入交换和 4 MiB 的复核交换组成。”原文容易被读成实测值，现改为说明其来源。实验、数据与结论均未改变。

## 复现

在独立实验目录部署同一固定源码快照后，用 `capacity_sort.py single --output <SINGLE>` 跑单机对照。在 B 运行以下第一条命令并从 `READY` 读取端口。在 A 运行第二条命令，使用同一个 32 字节随机十六进制 nonce。随后在本机回收两个输出目录并离线重放。

```sh
entry=experiments/aclt-minimal-verifier-baseline/capacity_sort.py
python3 -B "$entry" serve --output B --address <B_IP> --source <A_IP> --port 0 --nonce <NONCE>
python3 -B "$entry" connect --output A --address <B_IP> --source <A_IP> --port <PORT> --nonce <NONCE>
python3 -B "$entry" replay A B
```

本轮证明固定交付容量模型下的双物理机可行性。它允许暂存于内存，存储上限仅约束最终交付镜像。若允许改变输出编码、在镜像外持久化或把完整交付转交外部存储，容量结论需重算。排序当前经独立实验入口运行，与整数向量切片共用规范编码、分域摘要和分帧机制。后续仍需验证两种任务族能沿用同一套派发预留、接纳和交接流程。
