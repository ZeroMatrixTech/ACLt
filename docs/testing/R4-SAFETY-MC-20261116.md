## 授权、锁与凭据

- **授权：** 物理机使用依据 #128 决定 2（首次公开发行阶段）。
- **凭据：** 双机配置放在仓库外，权限 600，只含 `ssh_target`、`host_a_lan`、`host_b_lan`、`remote_root` 四个字段。B 的 `remote_root` 是本轮新建的私有目录（700）。真实地址、用户名、路径和密钥都不入库。
- **锁：** 每个 run 用一把 A 锁和一个 B agent 会话。锁记录、运行窗口和宿主观测都用 A 侧同一个 UTC 时钟。B 锁在会话建立时由 agent 确认，会话结束后由严格主机密钥的 SSH 探针确认已释放。
  - 检查器逐个核对了 64 个 run：锁记录都属于本 run，A、B 各有一次 `held` 和 `released`，B 嵌套在 A 内，运行窗口落在公共锁窗口内，每个阶段各有一次开始和回收观测。
  - 实跑前后 A、B 两端的锁都空闲，没有残留 QEMU。
- **运行时间（UTC，2026-11-16）：**

## 实跑命令

在 `experiments/aclt-minimal-verifier-baseline` 下执行；私有路径用占位符表示：

```sh
XDG_RUNTIME_DIR=/tmp python3 -B montecarlo.py run --seed <种子> --runs 16 --profile \
  --backend dualhost --config <私有配置> --kernel <内核> \
  --output <证据根>/pass<N>/seed-<种子> --accel tcg --timeout 300
```

两个 pass 用同一个源码提交和同一份配置，输出到不同目录，各自独立运行。

## S1–S7 检查

离线检查器从种子独立重建调度、profile 和 job，自己累计预算、接纳和发布，并逐个 run 核对：

- 宿主日志 `host.cbor` 与来宾副本 `guest.cbor` 一致，轮次正确；
- 服务方帧逐字节绑定，并由执行器重算答复；
- 注入记录、退出观测和关闭观测；
- overlap 的悬挂意图是未派发的 `RESERVE`；
- 交接后所有来宾都是新启动；
- 锁和时间窗口；
- 拓扑、放置与镜像摘要；
- 环境与源码身份；
- 归档清单。

检查器不依赖被测引擎的预算、接纳或发布守卫。

## 残余风险与边界

- **公开重放：** 外部复核者拿不到摘要相同的执行器，而自行构建的执行器会嵌入他们自己的路径，摘要对不上，所以无法用公开包完整重放 `check`，只能校验清单和查看证据内容。要做到公开可重放，需要让执行器的构建与路径无关，这要另开代码条目。
- **跨 VM 口径：** 按 R1 第 4 节，每个来宾 VM 视为一台独立机器。两台物理主机属于同一操作者、同一 LAN、可能同一供电域，不构成独立故障域，本文也不主张物理隔离。
- **协调者假设：** 协调者的行为按 R1 第 8 节的“固定派活、协调者可信”两条假设处理；自利协调者不在范围内。
- **两遍的含义：** “两遍可复现”只说明在相同的源码、执行器、种子和配置下，确定性投影逐字节一致；它不是统计结论。
- **TG-6：** [#123](https://github.com/ZeroMatrixTech/ACLt/issues/123) 保持 OPEN，R4 不依赖故障过程模型。
