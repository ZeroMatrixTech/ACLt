## 冻结题目相同才复用

按 [#120 维护者决定](https://github.com/ZeroMatrixTech/ACLt/issues/120#issuecomment-6881846750)，目标槽位就绪后构造冻结题目，并要求其 `question_id` 与源接受回执完全一致。题目摘要包含判题规则、工件、输入和资源上限。依赖槽位的输入来自本次已接纳结果，源回执仍保留原依赖绑定。首次接纳记录在目标执行日志中，绑定源执行、源槽位、源接纳摘要及冻结题目摘要。来宾重核原验证帧，宿主将原双端帧和源账完整重放。源执行历史费用独立保留。

| 场景 | 结果 |
|---|---|
| 树形变平铺，冻结叶序不变 | 同一整题，计划与执行身份改变。平铺执行四个槽位由 `REUSE` 接纳，包括依赖槽位 2。无 `RESERVE` 或 `SOLVE`，新增 gas 为 0，保留源执行的 32,938 gas。两次发布均为 `[2,3,4,11]`。 |
| 跨槽位本地回归 | 重复字面量使两个源槽位的冻结题目相同。目标槽位按本次位置接纳另一源槽位的证据。依赖就绪后复用其结果，最终为 `[2,2,4,11]`。 |
| 复用负例（本地回归） | 资源上限变化、依赖输入变化、缺失源接纳及错误执行或回执绑定被拒绝。完全相同的重传幂等，冲突接纳被拒绝。 |

## 协调轮次与双写者停止

按 [#121 维护者决定](https://github.com/ZeroMatrixTech/ACLt/issues/121#issuecomment-6881847017)，唯一指派和协调轮次作用于一次执行。宿主确认旧进程退出后重放原账并持久追加 `HANDOFF`，递增轮次。其余受控写入都携带写入轮次。轮次过期的孤立写入被拒绝。两个不同轮次的写入意图在宿主仲裁入口重叠时，宿主留证并撤销尚未提交的写入意图，暂停派发与发布。

| 场景 | 结果 |
|---|---|
| 正常交接 | 轮次 0 完成一片并退出，轮次 1 继承同一执行、账目与接纳。只发送剩余三片，发布 `[2,3,4,11]`，共 32,938 gas。 |
| 旧协调器在运行、孤立旧写入 | 本地进程回归中，旧进程未退出时拒绝重新指派。退出后指派成功。旧轮次单独迟到的写入被拒绝，未触发双写暂停。 |
| 重叠写入 | 轮次 1 来宾请求首次剩余分片预留时，测试驱动以独立宿主进程提交轮次 0 写入意图。两个原始写入意图进入同一宿主入口，触发 `PAUSED`。预留未提交，后阶段没有求解帧和发布文件。唯一宿主日志止于 `HANDOFF`，已计 8,232 gas、预留为 0。 |

重叠场景测试的是宿主观察到两个同时在处理的写入意图时的停止路径。故障注入进程模拟旧轮次写入，不声称旧来宾实际上同时重新启动。适用范围为可信单宿主、宿主掌握进程生命周期和无在途交接。跨宿主选主、分区、宿主回滚及自动恢复留给后续条目。
