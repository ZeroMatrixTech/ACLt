# FM-S1b：政策、终态费用矩阵与 Receipt 内容绑定

日期：2026-10-28；起点 `ddc171dde574018d53aa3060be28492f186132ae`。沿[FM 计划](../07-roadmap/formal-migration-plan.md)与 ADR-0007 推进，不新增路线或协议能力。

## 已完成的限定实现

[候选 schema](../../schemas/formal-migration/policy.json)、[合约/规则映射](../../schemas/formal-migration/policy.md)、[固定向量](../../tests/formal_migration/policy-vectors.json)与独立 Python/Rust 实现已形成。政策内容先冻结/摘要，Receipt 单向引用；叶子封闭 schema 禁止 Receipt 回指与任意 parent，避免互相摘要。输入对象解析为规范 i32 向量，输入可用期限覆盖 deadline；八个执行/环境/来源/等价/暴露/可用/部署/审计组件显式 hash-pinned。组件 fixture 是占位内容，字节绑定不证明 RIR/runtime 或正式 Profile conformance。

仅 Requester 预付整数测试资产，执行/验证/存储/退款储备分桶，uint64 求和无溢出且金额均受桶/总预算限制。108 个进程组合加 3 个全缺失、零费用的创建/规划/不支持退出格，共 111 行。全覆盖仅指候选费用表，不证明所有组合可达或允许客户端声明履约。COMPLETE/MISSING/HOST_FAULT 的权威判定与终态/故障归因仍在 FM-S2/S3；audit-only 无 ACCEPT/TRUSTED。

Requester 使用 S1a 固定 suite 签完整 Receipt 内容及专属 tag；签名不参与内容摘要。调用方必须持有独立预期 Receipt/Requester pin 与显式时点。改政策、输入、资源或执行组件后旧引用拒绝；合法重绑定产生新 Receipt 摘要；新政策仍用旧签名/调用方 pin 则拒绝，重签及更新预期后通过。改变非 RIR 字段不改变 RIR 引用。

## 实际证据

- 28 条固定向量（7 正例、21 负例）；12 个新增默认回归方法。
- 每端 196 项独立对拍：固定 raw/typed view、全部 111 费用格、跨 scope/预算/缺件/循环/未知 schema/过期与旧引用拒绝、合法重绑定及临时新密钥重签。

- 完整 `make test` 退出为零：默认 335 个方法（原 323 + 新增 12）；原 S1a 179 项与 Claim 29,766 项对拍通过，既有 state3 差分/20 次 sanitizer 运行和多节点/权威本地测试通过，FM-S1b 196 项对拍通过。清单/提交差异和源码包另行核对，实际输出与日志保留于同一证据根。开发期发现的测试重绑定覆盖负例和 Rust 内部 map 构造顺序比较问题已修正；保留原失败日志/初始向量，不弱化规则或复用历史通过记录。
