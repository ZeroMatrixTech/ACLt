## 本轮解决什么问题

此前只有 RUN 与 DONE；命令报错不一定代表任务永久结束，也没有任务整体期限或持久化的恢复次数上限。本轮把这些判断落到状态文件中。

| 条件 | 处理规则 |
|---|---|
| 临时存储错误、校验失败 | 命令拒绝；没有成功保存新的终止状态，就不能宣称任务已永久终止 |
| 分块尝试次数耗尽 | 保存 FAILED / ATTEMPTS；以后不能接收成功结果 |
| 恢复次数耗尽 | 保存 FAILED / RECOVERIES；以后不能推进任务 |
| 整体期限到达，尚未发布 | 保存 EXPIRED / DEADLINE；停止并清理计算进程 |
| 完整结果已发布，响应丢失 | 恢复核对内容，补记或读取 DONE；后来的期限不推翻已完成发布 |
| 辅助日志缺失或伪造完成事件 | 仍以状态和核对后的结果为准，不能把日志当成任务完成证明 |

发布前进行期限检查；这是调度器观察到的时间顺序，不承诺硬链接系统调用在精确的墙钟时刻完成。保存终止状态失败时，恢复会重新根据仍然保存的次数和期限作决定。

## 明确的边界

- 运行记录版本为 `ACLT-STATE-2`；旧记录明确拒绝，不自动迁移。旧任务应由旧版本结束，新版本使用新运行目录。
- 默认整体期限 300 秒、最多恢复 32 次；新建时可指定，恢复时不能通过命令行更换。
- 使用 Linux 开机时间并绑定启动标识。同次系统启动内恢复有效；操作系统重启后拒绝自动恢复。没有验证物理断电恢复。
- 已结束任务的重复读取不消耗恢复额度；只有继续未结束任务时才预留额度。
- 辅助日志不保证完整，不支持以它为依据重建权威状态，也没有防恶意修改或分布式最终性。
- 此版只补了部分累计资源控制：尝试次数、恢复次数、整体期限和原有进程上限。显式累计验证工作预算、日志及运行目录存储配额仍未实现，不能宣称所有资源消耗已封顶。
- 同一用户可同时改状态与校验值；本轮不提供敌对本地用户隔离。
- 没有付款、网络参与者、完整协议终止原因集合或全量 P0-1B 实现。

## 对设计的实际支持

本轮支持三项局部工程结论：已保存的永久结束决定不能被后来的结果推翻；恢复可以以权威快照保留已接受工作；先记恢复额度再工作，可以避免通过重启返还这部分额度。

需要修正的表述是：“命令返回拒绝”不等于“永久失败”；“日志出现 COMPLETE”不等于“任务已经完成”；“限制重试”不等于“全部资源和资金损失有上限”。这些测试不证明整个协议安全，也不改变统计验证所需的参与者独立性前提。

下一批优先补累计验证工作和存储配额，以及它们与永久失败的处理规则。随后再接任务条件绑定、多原因判断和两机通信。
