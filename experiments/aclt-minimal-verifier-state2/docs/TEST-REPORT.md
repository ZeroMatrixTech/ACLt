# 单物理电脑基础验证报告

本文保留基础 80 个案例/场景的说明；这些测试已在恢复版本上重新通过。新增恢复测试见 [恢复测试报告](RECOVERY-REPORT.md)。

日期：2026-10-02。范围：单台 Ubuntu 主机内的真实进程，不含跨机器通信。

## 环境和结果

- Ubuntu 26.04.1 LTS，x86_64。
- G++ 15.2.0，C++17；Ubuntu 官方 Rust 1.93.1。
- 两个语言实现均成功编译；无外部 Cargo 依赖。
- 基础验证：68/68 通过。
- 多进程端到端场景：12/12 通过。
- 示例：输入 10 个整数，分成 3 块，总和 28，最小值 -7，最大值 12。

## 基础验证覆盖

35 个正常案例（含 30 组固定种子随机输入、100,000 个最大正值和最大负值）；14 个结果或输入篡改案例；11 个非法输入；5 个非法分块参数；1 个结果文件超限；1 个全部 ASCII 空白字符案例；1 个 100,000 块的最大分块数量案例。

Python 独立核对正常案例的最终统计。C++ 非法输入退出码也被检查。拒绝案例包含错误块号、边界、数量、总和、最大最小值、漏块、重复块、乱序、多余字段及坏格式。

本轮发现并修复：C++ 与 Rust 对垂直制表符的解析不一致；100,000 个单元素块的合法结果会超过原 2 MB 结果限制。修复后的结果限制为 12 MB，输入仍为 2 MB。

## 多进程场景

| 场景 | 预期结果与实际检查 |
|---|---|
| 正常计算 | 启动不同 PID 的两个进程，再接受三个块，各一次 |
| 首次结果迟到 | 首次超时，第二次通过；之后旧结果到达并被忽略 |
| 首次统计错误 | 拒绝，第二次通过 |
| 首次进程异常退出 | 拒绝，第二次通过 |
| 首次永久等待 | 超时重派，第二次通过；旧进程被终止并回收 |
| 首次重复输出 | 拒绝，第二次通过 |
| 首次格式损坏 | 拒绝，第二次通过 |
| 首次尝试编号错误 | 拒绝，第二次通过 |
| 持续返回错误统计 | 两次用尽，失败，不发布最终结果 |
| 永久等待且只允许一次 | 期限到达后失败，并清理进程 |
| 异常退出且只允许一次 | 立即失败，不发布最终结果 |
| 无法启动计算程序 | 失败，不发布最终结果 |

额外断言：成功后用独立验证器命令再次检查保存的结果；每块只能接受一次；正常返回及失败返回后已启动 PID 均不存在；成功后重复使用同一目录被拒绝且既有结果不变；失败不记录 COMPLETE。

测试用 500 ms 期限注入 1,000 ms 延迟。机器极度繁忙时，正常任务也可能超时，这是期限规则的预期行为，不能将其解读成统计错误。

## 复现与证据

执行 `bash scripts/run-ubuntu.sh`，多进程测试摘要写入 `build/process-tests.json`。执行 `bash scripts/demo.sh slow` 可保留并检查完整的迟到结果事件记录。`docs/validation-output.txt` 保存本次运行输出。

当前环境的 Rust 官方软件包解包在本地 `.toolchain/` 中使用，没有系统安装；交付包不含该工具链、下载包或编译产物。接收方可按 README 使用 Ubuntu 官方软件源安装工具链。
