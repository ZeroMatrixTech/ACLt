# 调度器强制终止后的恢复测试

后续更新：这 12 个场景继续保留并通过；新增随机中断与存储故障测试见 [最新批次报告](BATCH-REPORT.md)。最终发布现在采用核对后不覆盖目标的硬链接，原场景中的“改名”应理解为最终结果已发布。

日期：2026-10-02。环境：Ubuntu 26.04.1 LTS、G++ 15.2.0、Rust 1.93.1。范围：一台电脑，操作系统持续运行，SIGKILL 调度器。

## 结论

**12/12 恢复场景通过**，测试实际发送 13 次 SIGKILL。原有 68 个基础案例和 12 个多进程场景也通过。恢复测试的进程监测最大值为两个存活计算进程；该采样是辅助证据，并不独立证明没有任何瞬时超限。

每个恢复场景在明确的步骤暂停后再被终止，不靠固定延迟猜测位置。R10 连续终止两次，所以 12 个场景包含 13 次强制终止。

## 实现变化

- 每次占用尝试额度和接受结果时保存完整进度；保存顺序为临时文件、同步、改名、同步目录。
- 恢复时检查格式、SHA-256、参数、输入快照、每块次数与统计，以及计算程序内容；校验码用于发现损坏，不能替代签名。
- 新增 `coordinator resume RUN_DIR`；不覆盖原运行、不返还已消耗的尝试次数。
- Linux 文件锁由调度器及计算进程共同持有。计算进程启动前设置父进程死亡 SIGKILL，并检查父进程是否已变化，防止设置保护时的竞争。
- 所有未保存为成功的旧尝试在重启后失效。尝试次数已用尽时恢复失败；已经保存成功的块重新核对后直接使用，不重新派发。
- 最终结果已存在时先核对完整进度与结果内容；缺少完成标记可以补齐，重复恢复不重复派发。

## 场景与结果

| 编号 | 实际测试 | 结果 |
|---|---|---|
| R01 | 输入与进度保存后终止，重新启动 | 通过：正常完成 |
| R02 | 占用第 1 次额度后、启动前终止 | 通过：从第 2 次开始，不返还额度 |
| R03 | 两个 C++ 进程在测试门处同时存活，终止调度器 | 通过：旧进程退出并由测试驱动回收，恢复后重新派发 |
| R04 | 第 0 块结果已写出、尚未保存为成功时终止 | 通过：旧尝试失效，第 2 次通过 |
| R05 | 第 0 块成功状态保存后终止 | 通过：该块不再派发，不重复计入 |
| R06 | 已记录超时、尚未派发重试时终止 | 通过：第 1 次仍失效，次数保留 |
| R07 | 最终临时结果写出后终止 | 通过：核对已保存块后发布，不重新计算 |
| R08 | 最终结果已改名、完成状态尚未保存时终止 | 通过：核对既有结果，补齐完成状态 |
| R09 | 第一个恢复进程持锁时同时启动第二个；重复恢复完成任务 | 通过：第二个被拒绝，完成任务不重复派发；另检查外部持锁也能阻止恢复 |
| R10 | 两次均在占用额度后终止，最多允许两次 | 通过：恢复明确报告次数耗尽，不发布结果 |
| R11 | 截断记录、破坏校验、改输入、制造重新计算校验后仍非法的次数 | 通过：四种情况均拒绝恢复，不启动计算 |
| R12 | 重启占用第 2 次额度后重新写入正确的第 1 次结果文件 | 通过：旧文件不被采用，仅接受第 2 次结果 |

R12 是延迟文件重放测试：因为旧进程会随调度器死亡，所以不是让一个旧进程在重启后继续执行。未重启情形的真实迟到进程仍由上一轮 `slow` 场景覆盖。

## 尚未覆盖

- 操作系统崩溃、物理断电、磁盘损坏、磁盘写满、网络文件系统语义。
- 在每条指令或每次文件写入中途随机终止；本轮只覆盖列出的明确暂停点。R11 通过人为破坏记录验证拒绝行为。
- 任意恶意计算程序、任意后代进程、运行记录被有意重写并重新计算校验。
- 两台物理电脑、性能收益、付款或协议整体正确性。

当前恢复要求输入目录和原计算程序仍在原路径，且程序内容未改变。有效 SHA-256 不表示来自可信方。事件日志可能在中断时缺少最后一条消息，恢复只依赖核验后的进度记录。

此前建议的随机中断、写入失败及损坏结果测试已在下一批次完成，见最新批次报告。原项目 P0-1B 仍不能据此关闭。
