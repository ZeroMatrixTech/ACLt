# ACLt 最简验证机 · 阶段 2 语义验收

范围为 `aclt.exp.rir-stats-exact@1` 下的固定 `stats-int-v1` 工件及小程序向量。本文记录候选执行规则与本地验收。运行时准入仍以[独立 stats-core 的支持契约](../aclt-rir-stats-probe/independent-contract.json)为准，协议语义以现有规范和 ADR 为准。

## 初始状态与输入输出

`Question` 固定工件、一个输入字节串和 gas、输出字节数、调用深度、内存页四个上限。工件的规范解码、模块类型和静态上限沿用 stats-core。实例化令内存为两页零值字节（每页 65,536 字节），全局变量取模块声明的初值，输出为空。先计实例化费 `4096 × 2 = 8192`，再从 `run` 进入深度为 1 的栈帧。帧包含当前指令、操作数栈、局部变量和控制标签。参数取调用实参，其余局部变量置零。

`stats-int-v1` 的输入是小端 u64 分块大小、小端 u64 元素数、随后等量的小端 i64。每个输出行依次是小端 u64 行号、起始偏移、长度，以及小端 i64 的和、最小值、最大值。完整的输入范围与程序主动终止码见[负载的二进制约定](../aclt-rir-stats-probe/README.md#frozen-experiment-wire-acltrirstats-wire1)。小程序向量沿用同一宿主 ABI。

## 单步规则

每一步先按当前指令和操作数计算成本 `c`。若 `gas_limit - gas_used < c`，以 `TRAP_GAS_EXHAUSTED` 终止，当前指令的费用和效果均不计入结果。余额足够则先把 `gas_used` 加上 `c`，再应用该指令的效果。已扣费用保留到正常返回或语义 trap。下表列出固定统计工件代码段实际出现的 31 个操作码，另列两个用于验收的小程序指令。

| 指令 | 成本 | 语义效果 |
|---|---:|---|
| `block`、`loop`、`br`、`br_if`、`return` | 1 | 块和循环建立空结果控制标签。分支按标签深度跳转并恢复目标标签的栈高度。`br_if` 弹出条件，非零时跳转。`return` 结束当前函数。跳转回 `loop` 时按候选执行器规则再次计 1，再从循环体开头继续。`end`、`else` 是分隔符，费用为 0。 |
| `unreachable` | 1 | 触发 `TRAP_UNREACHABLE`。 |
| `call` 到模块内函数 | 4 | 使用声明类型取得实参并新建帧。若当前深度已到上限，触发 `TRAP_CALL_DEPTH`。 |
| `call` 到导入函数 | 见下表 | 应用宿主 ABI，调用深度保持原值。 |
| `local.get/set/tee`、`global.get/set` | 1 | 读取值入栈，或弹出栈顶写入变量。`local.tee` 写入局部变量并保留栈顶。 |
| `i32.const`、`i64.const` | 1 | 将立即数的低 32 位或 64 位压栈。 |
| `i32.eqz/ne`、`i64.eqz/ne/lt_s/lt_u/gt_s/le_u/ge_u` | 1 | 按指令指定的有符号或无符号解释比较，压入 i32 的 0 或 1。 |
| `i32.add/sub`、`i64.add/sub/shl` | 1 | 加减按位宽取模。`i64.shl` 的移位量为右操作数模 64，结果保留低 64 位。 |
| `select` | 1 | 弹出条件与两个候选值，非零取较早入栈者，零取较晚入栈者。 |
| `i64.load/store` | 2 | 有效地址为无符号 i32 地址加静态偏移。若地址加 8 超过内存大小，触发 `TRAP_MEMORY_OOB`，否则按小端读写 8 字节。 |
| 小程序的 `drop` | 1 | 丢弃栈顶。 |
| 小程序的 `i64.div_s` | 8 | 有符号除法向零截断。除数为零触发 `TRAP_INTEGER_DIVIDE_BY_ZERO`，最小 i64 除以 −1 触发 `TRAP_INTEGER_OVERFLOW`。 |

宿主 ABI 只能读取题目绑定的输入、访问该实例内存、追加输出或主动终止。导入调用按下表直接计费。范围检查在扣费后进行；输入索引、区间或内存区间无效时触发 `TRAP_HOST_ARGUMENT`。

| 导入 | 成本 | 语义效果 |
|---|---:|---|
| `input_count()`、`input_len(i)` | 4 | 返回 1，或在索引为 0 时返回输入字节数。 |
| `input_read(i, off, dst, n)` | `16 + ceil(n/8)` | 将输入区间复制到内存。 |
| `output_write(src, n)` | `16 + ceil(n/8)` | 将内存区间追加到输出。先检查内存范围，再检查累计输出上限，超限触发 `TRAP_OUTPUT_LIMIT`。 |
| `abort(code)` | 1 | 以 `ABORT` 终止，结果记录该 u32。 |

正常返回的 `Outcome` 为 `{outcome: OK, gas_used, output}`。trap 结果包含原因和 `gas_used`，其中 `ABORT` 另含 `abort_code`，部分输出丢弃。以上 trap 字面值沿用实验执行器。验证比较规范 CBOR 的完整字节。宿主无法产生结果时，实验接口返回执行错误，提交仍待判定。

## 固定向量与单侧偏差

| 向量 | 手算 | gas 上限 | 规范结果 |
|---|---|---:|---|
| 写出 42 | 实例化 8192，四条常量各 1，写内存 2，输出 8 字节的导入调用 17 | 8215 | `OK`，已用 8215，输出 `2a00000000000000` |
| 除零，费用恰好足够 | 实例化 8192，两条常量各 1，扣除法费 8 后执行 | 8202 | `TRAP_INTEGER_DIVIDE_BY_ZERO`，已用 8202 |
| 除零，费用差 1 | 除法前已用 8194，余 7，当前指令未扣费 | 8201 | `TRAP_GAS_EXHAUSTED`，已用 8194 |

`make test-minimal-verifier` 用这些预期检查 Python 的结果字节，再提交给 Rust 验证。负例分别更改结果字节、trap 原因和 gas，并检验跨题提交、替换工件或输入字节。统计工件的指令清单也有固定回归。

单侧偏差测试在临时目录将 Rust 的 `i64.div_s` 费用从 8 改为 7。对上限 8201 的同一道题，正常 Rust 接受 Python 的 gas 耗尽答案。改动后的 Rust 执行除法，得到除零且已用 8201，对正确提交返回 `REJECT / OUTCOME_MISMATCH`。测试核对两份规范结果的完整字节，并打印题目摘要和结果十六进制供复查。

证据限于上述局部语义和固定向量。关联问题为 [OQ-05 与 OQ-06](../../docs/07-roadmap/open-questions.md)，后续按各自关闭条件验收。
