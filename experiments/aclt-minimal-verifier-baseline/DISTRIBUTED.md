# ACLt 最简验证机 · 双机作业切片

首个可信双机作业使用固定的 `stats-int-v1` 工件、输入 `[3, -1, 5, 8, -2]` 和统计块大小 2。A 协调作业并计算 `[0, 2)`，B 计算 `[2, 5)`。A 验证 B 的提交，B 验证 A 的提交。两台机器在同一 LAN 上运行，SSH 用于部署、启动和回收取证文件。

## 切片与归并

- `prepare_job` 校验完整的统计输入，沿原块边界拆成两个连续非空区间并冻结每片题目。计划绑定原始工件和输入摘要、统计块大小、归并规则版本以及各片位置、区间和题目摘要。
- LAN 上使用现有的定长前缀 CBOR 帧传递切片题目和输入、答案与裁决。裁决绑定作业、切片位置、题目和答案字节。两个内容相同的切片可以共享题目摘要，归并以作业内的位置计数。
- `merge_job` 从完整输入重建计划与各片题目，逐项核对提交和裁决。每个位置恰好有一份已接受的 `OK` 后，按计划顺序恢复行号与元素偏移。切片的 `gas_used` 随各自结果留存。

设原统计块大小为 `k`，切片从 `s` 开始，且 `s` 是 `k` 的整数倍。切片行与原作业的对应统计块包含相同元素。每行的和、最小值、最大值和长度因此相同。将切片行号加 `s/k`，将行内起始偏移加 `s`，按完整且无重叠的计划拼接。在整题和各片均正常返回的条件下，该输出与完整输入的参考运行逐字节一致。

## 资源语义审计

双机入口按[可复查的分片成本公式](GAS-ALLOCATION.md)为各片分配 gas，可选的分片求解总额度在派发前检查。

对本用例，完整输入正常运行使用 9425 gas，两片分别使用 8719 和 9018。将同一个 9018 gas 上限同时用于完整输入和各片时，两片均为 `OK`，整题返回 `TRAP_GAS_EXHAUSTED`，已使用 9016。固定回归保留该反例。分片重做实例化和部分控制流程，当前结果组合规则只承诺正常返回条件下的输出等价。保持整题资源语义仍待定义和证明。

## 复现与证据

本地复查使用 `make test-minimal-verifier`，覆盖正常归并、乱序、缺片、重复计入、错绑提交、同内容切片与确定性 trap。消息处理和两个执行入口可在本地测试。物理机验收按 [DUALHOST-SSH-1](../../docs/08-governance/dualhost-ssh-validation.md) 执行，从 A 的已提交源码运行以下命令。选择 B 的已验证 SSH 地址与两端的新运行目录。

```sh
python3 -B experiments/aclt-minimal-verifier-baseline/dualhost.py run \
  --peer '<B_USER>@<B_LAN_IP>' \
  --remote-root /tmp/aclt-verifier-first-job \
  --output /new/local-evidence-directory
```

驱动分别构建 A 与 B 的 Rust 执行器，通过真实 LAN 交换两次请求和回复，回收 B 的原始帧并和 A 逐字节核对。输出目录记录源码提交与摘要、工具版本、双方消息、裁决、归并输出及参考输出。两端的日志和物理拓扑由受信实验操作者复核。成功结果记录在 `result.json`。整题参考运行属于验收步骤，使用既有 Python 求值器。

[广度优先拆分与递归归并](TREE.md)扩展同一双机入口，比较相同叶子下的平铺与递归结果。

## 本地双来宾入口

物理双机暂停期间，同一入口可在单宿主上用两个 QEMU 来宾承担 A、B：两端各有独立内核、根文件系统、证据盘和 TCP 栈，作业帧经 QEMU socket 链路传输，不走宿主外部网络，也不需要 root、tap 或 bridge。

```sh
make test-minimal-verifier-multivm \
  MULTIVM_KERNEL=/path/to/vmlinuz \
  MULTIVM_OUTPUT=/tmp/aclt-multivm-flat
```

驱动在启动前用与双机入口相同的 `prepare_job` / `prepare_tree` 算出叶子数并写入两端内核命令行，来宾因此能在第一条请求上校验计划形态。验收比对两端 `boot_id`、角色、socket 地址方向、源码提交、执行器摘要、逐片执行/验证角色交替、gas 守恒、输出摘要与长度，以及两端请求/响应帧的逐字节相等。

结果见[本地双来宾验证第 1 轮](../../docs/testing/MULTIVM-20261112.md)：平坦两片、显式预算两片和树归并三片全部通过，归并输出与单机参照一致。这是来宾级证据，不替代物理主机分离、宿主级故障或统计独立性结论，也不改变 [DUALHOST-SSH-1](../../docs/08-governance/dualhost-ssh-validation.md) 的物理双机要求。
