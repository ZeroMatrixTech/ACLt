# 上一轮结果整理与下一步

历史记录：本文对应恢复功能加入前的版本。最新状态为全部 182 个案例/场景通过，见 [最新批次报告](BATCH-REPORT.md)。

## 本轮结论

单机计算与故障重派闭环已通过本轮列出的测试。当前状态：**单机基础试验通过；恢复能力待实现、待测试**。本结论不修改 ACLt 原项目的 Gate 或 P0-1B 状态。

| 检查层次 | 实际结果 | 可以据此确认 |
|---|---|---|
| 整数计算与输入检查 | 68/68 案例通过 | 两种语言在所测输入上保持一致，并拒绝列出的错误 |
| 单机多进程流程 | 12/12 场景通过 | 在调度器持续存活时，能重派失败工作、忽略旧结果并限制尝试次数 |
| 交付包复现 | ZIP、源码校验、全新目录构建及全部测试通过 | 不依赖原目录里的编译产物；复现仍使用同一主机已有编译器 |

总计 80 个案例/场景通过，**不是 80 条协议规则完成，也不是整个系统的完成率**。预期失败的任务以“确实失败且不发布结果”为通过条件。

## 本轮修复

1. 统一六种 ASCII 空白字符的解析，补上垂直制表符案例。
2. 输入大小限制保留 2 MB；结果上限调整为 12 MB，避免最大分块数量下误拒绝合法结果。
3. 加入真实子进程的尝试编号、期限、重派、旧结果拒绝与尝试次数上限。
4. 每个成功块只计入一次，全部通过才发布最终结果，拒绝覆盖已有运行目录。

## 尚未得到的证据

- 调度器被强制终止后恢复；操作系统崩溃或断电后的持久性。
- 两台物理电脑之间的通信或独立参与者行为。
- 计算速度或成本收益：验证端完整重算，每个计算进程仍读取全部输入。
- 敌对程序隔离、身份、签名、付款及模拟账务。
- 换一台全新 Ubuntu 电脑安装工具链后的复现。

本轮对计算进程“异常退出”的注入是返回非零状态，不覆盖所有真实崩溃方式。500 ms 是故障测试参数，不是部署建议。基础案例在最大分块数量下检查结果格式，但没有启动 100,000 个进程做负载测试。
