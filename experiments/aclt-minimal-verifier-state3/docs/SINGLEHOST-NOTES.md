# 单机扩展说明（2026-10-03）

## 新增本地规则

新建入口可在整体期限和恢复次数之后增加：验证比较单位上限、运行目录字节上限、日志字节上限。

```sh
target/debug/coordinator examples/input.txt 4 build/worker build/new-run normal 500 2 300000 32 10000000 67108864 1048576
```

默认值：验证比较单位 10,000,000；目录普通文件逻辑字节 64 MiB；日志 1 MiB。参数上界分别为 100,000,000、256 MiB、16 MiB；目录上限至少 4096 字节，实际须能容纳任务记录与预留空间。其他参数沿用上一版。不能通过恢复命令改额度。

- 比较单位按该次核验涉及的输入整数个数收取，先保存再核验。分块核验、最终全量核验及未完成任务恢复时的已接受分块核验计入。中断不退款。解析、哈希、状态序列化、打印及已发布结果的只读复查不计入此计数，故不能称为完整 CPU 计量。
- 日志每次追加之前检查总字节，超限不再追加，保存 FAILED / LOG。
- 对本程序平铺目录内普通文件的逻辑长度作保守预检，预留终止记录与在途输出空间。可能提前拒绝；不代表磁盘块、inode、子目录或外部用户写入被强制限额。物理磁盘已满时，终止状态也可能保存失败，只能报告存储错误。
- 直接子进程同时受 Linux 文件大小限制：标准输出与标准错误各最多 256 字节。本轮不提供任意程序的 CPU、内存、后代进程或网络沙箱。
- 额度耗尽记录 FAILED / VERIFY、STORAGE 或 LOG。它们是本地试验原因，未冒充完整协议的资金原因或事件 DAG 判决。
- `contract.txt` 单独固定任务 ID、整数统计规则版本、输入摘要、程序路径与摘要、分块、超时、尝试次数、整体期限、启动标识及资源上限。恢复比对原约定。它不是签名；有权同时改两个文件的用户仍可改写试验。
- 单块输出带任务 ID，拒绝把另一个任务的正确数字结果当成本任务执行证据。独立 worker 的原两参数统计入口继续可用。

## 验收

259 个场景通过；新增 55 个包括验证预算的零/恰好/少一单位、预留中断、计数写入失败、恢复核验收费、发布后额度用尽、日志上限、目录不足、两个输出通道超限、跨任务重放、逐项固定参数变更、约定丢失/版本改变、同时到期与预算不足、完成之后日志报错，以及全部声明参数的上下界与越界拒绝。

另有 204 组固定种子数据、408 次结果变异、20 次 AddressSanitizer/UndefinedBehaviorSanitizer/LeakSanitizer 检查、12 种非法输入、22 个 Rust/C++ 原因归约向量。原 Python 原因归约器也进行了全部子集和排列测试；仅覆盖该小函数，非全协议独立验证器。

系统强制终止测试不等于物理断电。`state.txt` 仍是权威快照，辅助日志不是可重放的最终性证明。旧状态版本不自动迁移。完整主仓库范围、缺口与修复见 `docs/testing/SINGLEHOST-REPORT.md`。
